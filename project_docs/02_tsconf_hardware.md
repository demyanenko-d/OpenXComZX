Собрано из локальных источников в `REF/`. Самый авторитетный источник на
уровне кода — эмуляция TSL в Unreal Speccy; сверено с TS-BIOS, Wild
Commander и плагином plasmatw. **На реальном железе ничего не проверялось.**

> **Внимание:** `REF/src_sdcc/inc/tsconf.h` содержит серьёзные ошибки в
> номерах регистров и кодах DMA (см. §12). Как справочник не использовать;
> в проект брать только исправленную версию.

## 1. Порты и карта регистров

- **Адресация:** каждый регистр TS — порт `(reg<<8)|#AF`, доступ
  `OUT (C),A` / `IN A,(C)` [UIO:182 `ts_ext_port_wr`].
- **Читаются только:** `#00AF` Status, `#12AF` Page2, `#13AF` Page3,
  `#27AF` DMAStatus [UIO:1012-1033]. **Остальные — только запись, держать
  теневые копии в ОЗУ** (WC держит теневые страницы в #6000–#6003 [WCMD]).
- Запись в неиспользуемые номера игнорируется; Unreal пишет в консоль
  «Illegal port! OUT (xxAF)» — SINF использует #FDAF–#FFAF как отладочный вывод.

Карта (по [UH] enum TSREGS, подтверждено [WCTS], [WCMD], [UDBG]):

## 2. CPU: частота, кэш, wait states, прерывания

### Частота (ZCLK, SysConfig биты 1:0)

0 = 3.5 МГц, 1 = 7 МГц, 2 = 14 МГц. 3 — «unk» в UDBG, Unreal считает 14 МГц;
FCLK утверждает 28 МГц (не проверено). Переключение мгновенное (FCLK).
TS-BIOS пишет `SysConfig = cfrq | (cach<<2)` из NVRAM; по умолчанию 3.5 МГц
с включённым кэшем [TBA:170-177].

### Кадр

320 строк x 224 такта (при 3.5 МГц) = **71 680 тактов на кадр, ~48.83 Гц**
[UDRAW, UINI]. Пиксельная частота 7 МГц → 448 пикселей на строку. **На 14 МГц
кадр = 286 720 тактов CPU.**

### Кэш

- 512 байт, прямое отображение, 16 бит ширина [UZ80:188-207]: индекс =
  addr[8:0], тег = {page[7:0], addr[13:9]}; промах при чтении заполняет
  2 байта; запись CPU инвалидирует 2-байтную запись (write-through) [UZ80:306].
- Работает только для окон с ОЗУ; окно 0 как ПЗУ (или W0_WE = 0) не кэшируется.
- **Запись SysConfig перезаписывает CacheConfig** значением #0F (если бит 2)
  или #00 [UIO:1448-1451] → **CacheConfig писать после SysConfig**.
- **Запись DMA не инвалидирует кэш.** Unreal инвалидирует весь кэш только
  при сбросе. Подтверждено практикой: SMAIN:635 — кэш включать «после
  inflate/load — DMA/страничный ввод-вывод портит кэш»; FCLK держит кэш
  выключенным всю сессию.
- WC пишет CacheConfig = #02 (только окно #4000) в TURBO/TURBOPL и #06 при
  сортировке [WCMD:21-22, 1030-1036, 1099-1107].

### Wait states (модель Unreal)

На 14 МГц промах кэша выравнивается на цикл DRAM 7 МГц [UZ80:56-95]:
**M1 — 7–8 тактов вместо 4, чтение памяти — 5–6 вместо 3**, запись без
штрафа. На 3.5 и 7 МГц ожиданий нет. SISR сбрасывает CPU на 7 МГц на время
каждой записи в AY, SAA, OPL — эмпирический обход медленных шин чипов.

**Вывод: 14 МГц без кэша — это заметно меньше 14 МГц. Кэш нужен,
но с ним нельзя давать DMA писать в страницы, стоящие в кэшируемых окнах.**

### Прерывания [SH, UC, UZ80, UINT]

| Источник | Вектор IM2 | Приоритет | Срабатывание |
|---|---|---|---|
| FRAME | #FF | 0 (высший) | луч достигает (VSINT, HSINT). Импульс `intlen` 32 такта; **теряется, если не принят вовремя** |
| LINE | #FD | 1 | начало **каждой** из 320 строк, если включено; защёлкивается до подтверждения |
| DMA | #FB | 2 | конец передачи DMA; защёлкивается |

- Подтверждение INT сбрасывает только флаг высшего приоритета; остальные
  сработают после EI [UINT:26-33].
- Запись INTMask сбрасывает ожидающие флаги выключаемых источников [UIO:1464].
- Таблица IM2: слова по адресам I:FB/FC, I:FD/FE, I:FF/(I+1):00. WC — I = #5B,
  вектор кадра в #5BFF. TS-BIOS сам работает в IM 1 [TBA:75].
- **Несколько кадровых INT за кадр:** перепрограммировать VSINTH/VSINTL/HSINT
  внутри ISR. SISR: `LD BC,#25AF` и 3x OUTI из таблицы → 14/28/56 INT за кадр.
- SH утверждает, что VSINTH биты 7:4 — «VINT_INC» (автоинкремент); Unreal
  хранит только бит 0 — не проверено.
- При активном vDOS прерывания не доставляются [UZ80:441].

## 3. Память

- **4 МБ = 256 страниц по 16 КБ** [Unreal `MAX_RAM_PAGES = 256`, UINI RAMSize=4096].
- ПЗУ 512 КБ flash = 32 страницы [UMEM:204].
- Окна #4000, #8000, #C000 — всегда ОЗУ (Page1–Page3) [UMEM:207-209].

### Окно 0 / MemConfig `#21AF` [UH, UMEM:174-205, WCTS]

| Бит | Имя | Смысл |
|---|---|---|
| 0 | ROM128 | то же, что бит 4 #7FFD |
| 1 | W0_WE | окно 0 доступно на запись; без него запись в окно 0 отбрасывается, даже для ОЗУ |
| 2 | W0_MAP_N | 1 = Page0 как есть; 0 = страница = (Page0 & #FC) \| bank, где bank = DOS ? (7FFD.4 ? 1 : 0) : (7FFD.4 ? 3 : 2) |
| 3 | W0_RAM | 0 = страница ПЗУ, 1 = страница ОЗУ |
| 7:6 | LCK128 | 00 = 512K (#7FFD биты 7:6 → биты страницы 4:3); 01 = 128K; 10 = авто; 11 = 1024K [UIO:725-755] |

**Для игры:** MemConfig = W0_RAM | W0_MAP_N | W0_WE → в окне 0 своя страница ОЗУ.

- Группа ПЗУ ts-bios.rom: +0 TS-BIOS, +1 TR-DOS 5.04T, +2 BASIC 128,
  +3 BASIC 48 [TBCMP].
- **Побочные эффекты #7FFD:** запись ставит Page3, **сбрасывает VPage в 5
  или 7** и ставит ROM128 [UIO:757-761]. #7FFD декодируется частично
  (A1 = 0, A15 = 0). **Родной код не должен трогать #7FFD.**

### Занятые страницы

TS-BIOS [TBD]: F4–F7 Virtual ROM, F8–F9 экран BIOS Setup, FA–FE драйверы
VDOS, FF ловушки VDOS (TBC расходится: txpage #F6, шрифт в #F7, vrompage #F8).

WC (подтверждено в WCMD):

| Страницы | Назначение |
|---|---|
| #00 | главный текстовый экран |
| #08 | буфер |
| #0B–#13, #14–#1C | каталоги панелей |
| #1D | буфер сохранения окон |
| #1E, #1F | позиции каталогов |
| #20–#5F | мегабуфер; видеобуферы GV1–GV4 в #20/#30/#40/#50 по 16 страниц |
| #60 | заголовки плагинов |
| #61–#A0 | код плагинов |
| #F0–#F3 | потоки панелей и плагинов |
| #F4–#F7 | DBPG, D5PG, D2PG, RPPG |

Только в SWC (не подтверждено исходниками WC): #01 шрифт, #02 код WC,
#05 FAT-движок, #09 второй шрифт, #A1–#BF TAP, #C0–#E7 RAM-диск vDOS,
#E8–#EF свободно, #F8–#FB VROM, #FC–#FD таблицы vDOS, #FE драйверы, #FF ловушки.

**Практическое правило:** автономный SPG, который не возвращается в WC, может
использовать **#00–#EF (240 страниц = 3.75 МБ)**. #F0–#FF не трогать, если
нужно сохранить состояние vDOS/WC; загрузчик SPG использует #F4–#F6.

## 4. Видео

### Разрешения (RRES, VConfig биты 7:6) [UDRAW `raster[]`]

| RRES | Разрешение | Строки картинки | Такты пикселей в строке 224 T |
|---|---|---|---|
| 00 | 256x192 | 80–271 | 70–197 |
| 01 | 320x200 | 76–275 | 54–213 |
| 10 | 320x240 | 56–295 | 54–213 |
| 11 | 360x288 | 32–319 | 44–223 |

### Режимы (VM, VConfig биты 1:0) [UDRW]

| VM | Режим | Устройство памяти | Выравнивание VPage | Индекс CRAM | Циклов DRAM на видимую строку |
|---|---|---|---|---|---|
| 00 | ZX | стандартный экран ZX с начала VPage | любое | GPAL<<4 \| BRIGHT<<3 \| ink/paper | 1 на 8 пикс |
| 01 | 16c | 4 бит/пикс, старший полубайт — левый пиксель; 256 байт/строку; холст 512x512 | `VPage & #F8` (128 КБ) | GPAL<<4 \| полубайт | 1 на 4 пикс (80 при 320) |
| 10 | 256c | 8 бит/пикс; **512 байт/строку**; холст 512x512 | `VPage & #F0` (256 КБ) | сам байт | 1 на 2 пикс (160 при 320) |
| 11 | Текст | 64 строки x 256 байт: символы +#00–#7F, атрибуты +#80–#FF; шрифт в странице `VPage^1` | — | GPAL<<4 \| полубайт атрибута | 2 на символ |

- Текстовый режим высокого разрешения: WC работает 80x25 при 320x200,
  80x30 при 320x240, 90x36 при 360x288.
- NOGFX (бит 5): вместо картинки — цвет бордюра, TSU продолжает рисоваться;
  освобождает циклы выборки картинки.
- **Адресация 256c:** страница = VPage + (y>>5), смещение = (y & 31)·512 + x.
- **Одна 256-КБ область 256c = два буфера по 256 строк; переключение GYOffs
  0 ↔ 256 даёт двойную буферизацию.**

### Скролл

GXOffs/GYOffs — 9 бит, заворачиваются на 512. Скролл X — только в 16c и 256c;
Y — во всех режимах.

### Защёлкивание регистров [UDRAW:614-662]

- VConfig, VPage, PalSel, GXOffs действуют с начала следующей строки.
- T0XOffs/T1XOffs — с задержкой 1 строка; T0GPage/T1GPage — 2 строки.
- **Запись GYOffs перезагружает счётчик Y на следующей строке** — следующая
  строка покажет строку картинки = GYOffs, а не GYOffs + текущая строка.
  **Сплит-экран (скроллируемая карта + неподвижная панель) — одна запись
  регистра в кадровом INT.**

### Палитра (CRAM)

- 256 слов по 16 бит: биты 14:10 R, 9:5 G, 4:0 B [UC `update_clut`].
- **На стоковом ZX-Evo (VDVER = 0, ШИМ-ЦАП) различимы только уровни 0–24**;
  25–31 насыщаются. Стандартные цвета ZX — 16 (обычный) и 24 (яркий).
  **Перевод 6-бит палитры VGA X-COM: `v24 = round(v6 · 24 / 63)`.**
  Канал = биты 4:3 — уровень 2-битного ЦАП, 2:0 — скважность ШИМ (+1 уровень
  на 0..7/8 периода); при уровне 3 ШИМ не добавляет — отсюда шкала 0..24
  [`REF/fpga/video/video_out.v`: `cred/ired`, таблица `pwm[]`].
- **Платы VDAC (VDVER ≠ 0): бит 15 слова CRAM — `vdac_mode`** (выводится на
  шину IDE, `REF/fpga/top.v` `ide_d[15]`). CPLD платы [`REF/vdac1/cpld/top.v`,
  `REF/vdac2/cpld/top.v` (`pal_sel`)]: **бит 15 = 1 — линейный RGB555**
  (`out = {in, 3'b0}`); **бит 15 = 0 — LUT совместимости с ШИМ** (0..24 →
  0..255 линейно, 25..31 → 255). Без бита 15 полные 5-битные значения
  «засвечиваются» (×31/24 с насыщением) — так было в порте до 2026-09-15.
  Эмулятор повторяет обе модели (`TS_VDAC=5BIT`, `update_clut`: `pwm_lin` /
  `<< 3`). **Целевая конфигурация игры — с VDAC:** `gfx_palette` ставит бит 15;
  без VDAC — пересчёт в 0..24 (запасной вариант).
- CRAM #F0–#FF при сбросе загружается цветами ZX.
- **Два способа записи CRAM:**
  - через FMAddr: FM_EN + A[15:12]; в этом окне 4 КБ: #000–#1FF — CRAM
    (little-endian: чётный байт держится, нечётный фиксирует слово),
    #200–#3FF — SFILE, #400–#4FF — регистры TS. Запись попадает и в ОЗУ под
    окном; окно только на запись. Пример: `FMAddr = #10`, LDIR в #0000,
    `FMAddr = 0` [WCTW:70-83, TBA `LD_PAL`];
  - DMA RAM→CRAM (§6).

### Бордюр

Регистр Border — полный индекс CRAM. `OUT (#FE)` ставит бордюр = #F0 | (v & 7).

## 5. TSU (тайлы и спрайты) [UC, UH, WCTS]

- TSU рисует в 512-пиксельный строчный буфер, накладываемый на картинку
  только в области пикселей (не на бордюр).
- **Пиксель TSU с индексом, у которого младший полубайт 0, — прозрачный.**
  В 256c TSU делит CRAM с картинкой.
- Координаты — от левого верхнего угла активной области, 9 бит с заворотом.
- **Порядок слоёв (снизу вверх): S0, T0, S1, T1, S2.**

### Тайловые слои

Два слоя, каждый — карта 64x64 тайлов 8x8, оба в одной странице TMPage:
строка r — смещение r·256, слой 0 — +0..127, слой 1 — +128..255.
Элемент (16 бит): биты 11:0 номер тайла, 13:12 палитра, 14 X-flip, 15 Y-flip.
Палитра = T0PAL/T1PAL<<6 | палитра тайла<<4 | пиксель. Тайл 0 пропускается,
если не включён TxZ_EN.

### Листы графики (тайлы и спрайты)

4 бит/пикс, 512 пикс ширина x 512 строк, 256 байт/строку, 8 страниц.
`адрес = GPage + ((tnum & #FC0) << 5) + (line << 8) + ((tnum & #3F) << 2)` —
биты 5:0 номера — 8-пиксельный столбец, 11:6 — 8-строчная полоса.
Графика тайлов — `GPage & #F8`; Unreal не маскирует SGPage — брать кратное 8.

### Спрайты

SFILE = 256 слов = **85 дескрипторов x 3 слова**:

| Слово | Биты |
|---|---|
| 0 | 8:0 Y, 11:9 YS (высота = (YS+1)·8), 13 ACT, 14 LEAP (последний спрайт слоя), 15 Y-flip |
| 1 | 8:0 X, 11:9 XS (ширина = (XS+1)·8, т.е. 8–64), 15 X-flip |
| 2 | 11:0 номер тайла, 15:12 палитра (индекс = палитра<<4 \| пиксель) |

Дескрипторы обрабатываются 0..84; биты LEAP делят их на три слоя спрайтов.

### Бюджет на строку (модель Unreal: лимита по количеству нет, только циклы DRAM)

- чтение карты: 8 циклов на включённый слой на строку;
- тайловый слой: всегда 46 тайлов (368 пикс) → 92 цикла;
- спрайты: 2 цикла на 8-пиксельный столбец видимой строки спрайта;
- бюджет = 448 − видео − CPU − DMA − TSU.
- Пример, 320x200 256c + один тайловый слой: 448 − 160 − 100 = 188 циклов
  ≈ 94 столбца спрайтов (~750 пикс) на строку до учёта CPU и DMA.

## 6. DMA [UC:105-540, UH, UIO, UDBG, TBC, WCTS, TBF]

**Биты DMACtrl:** 7 WNR (R/W), 6 OPT, 5 S_ALGN, 4 D_ALGN, 3 ASZ, 2:0 DDEV.

| Ctrl | Режим | Циклов DRAM на слово |
|---|---|---|
| #01 | RAM→RAM | 2 |
| #81 | **BLT1: RAM→RAM с пропуском нулевых пикселей источника.** ASZ = 0 — проверка полубайта (16c), ASZ = 1 — байта (256c) | 3 |
| #06 | **BLT2: dst = src + dst** по полубайтам/байтам; OPT = 1 — с насыщением (в UC; в UDBG не названо) | 3 |
| #04 | FILL: читает 1 слово, пишет len·num раз | 1 |
| #84 | RAM→CRAM (индекс CRAM = (DADDR>>1) & #FF) | 1 |
| #85 | RAM→SFILE | 1 |
| #02 / #82 | SPI→RAM / RAM→SPI | 1 (на железе упирается в SPI) |
| #03 / #83 | IDE→RAM / RAM→IDE | — |
| прочие | NOP | — |

(К коду режима добавляются флаги: ASZ #08, D_ALGN #10, S_ALGN #20, OPT #40.)

**BLT2 есть не в каждой прошивке** (найдено 2026-09-15 при разработке плана глобуса,
`globe.md`): режим `DEV_BLT2` собирается только под `` `ifdef XTR_FEAT ``
(`REF/fpga/common/dma.v:88–181`); `XTR_FEAT` определён в `REF/fpga/quartus_vdac/tune.v`
и `quartus_vdac2/tune.v`, а в обычной `REF/fpga/quartus/tune.v` закомментирован.
Целевое железо — с VDAC (прошивка VDAC), BLT2 там есть; без него — запасной путь на CPU.

### Длины

Пачка = DMALen + 1 слов (2–512 байт); пачек = DMANum + 1 (1–256). Максимум
128 КБ за один запуск.

### Адресация

- 22-бит физическая, по словам (бит 0 игнорируется), независимо от окон CPU.
- Без ALGN адрес идёт линейно через страницы.
- С S_ALGN/D_ALGN каждая пачка начинается с начала предыдущей + 256
  (ASZ = 0) или + 512 (ASZ = 1) — это шаги строк 16c и 256c.
  **Блит прямоугольника: DMALen = w/2 − 1, DMANum = h − 1, D_ALGN.**
- Гранулярность: чётные X и ширина в 256c; 4 пикселя в 16c.
- После передачи регистры адреса указывают за конец → следующий DMA может
  продолжать без перезагрузки.
- Пример: TS-BIOS чистит память RAM→RAM с адреса на себя + 2 [TBA `DMAFILL`].

### Работа

Старт — запись DMACtrl; ждать бит 7 DMAStatus (TS-BIOS RST 8:
`LD BC,#27AF / IN F,(C) / RET P / JR`). **Не писать регистры DMA во время
работы DMA.** INT по окончанию требует INTMask бит 2.

### Пропускная способность (из модели Unreal, не замер)

- DRAM 7 МГц: 448 циклов на строку, 143 360 на кадр.
- Приоритет: CPU и видео учитываются первыми, затем TSU, затем DMA.
  **CPU не останавливается.**
- 320x200 256c оставляет ~111 тыс. циклов на кадр → **~111 КБ RAM→RAM,
  ~74 КБ BLT или ~222 КБ FILL за кадр** при простаивающих CPU и TSU.
- Верхние и нижние строки бордюра (76 + 44) дают DMA все 448 циклов.
- Для сравнения: LDIR на 14 МГц — максимум ~13.6 КБ за кадр.

## 7. Звук

### AY/YM

`#FFFD` выбор/чтение, `#BFFD` запись [UIO:790-851]. TurboSound (схема
NedoPC «CHRV»): запись `%11111xxx` в #FFFD — бит 0 выбор чипа, бит 1 чтение
статуса YM2203, бит 2 FM (флаг FM выключен при бите = 1) [UIO:797-806].
SISR трактует бит 3 как «SAA clock off» (управляющий байт MultiSound).
Полярность выбора чипа расходится между источниками (§12). Частота AY
1.7744 МГц.

### SAA1099

`#01FF` адрес/управление, `#00FF` данные (A8 выбирает) [UIO:875]; частота
8 МГц. В режиме DOS #FF — системный порт Beta Disk. Схемы второго чипа в
локальных файлах разные (§12).

### Covox / SounDrive (только Unreal; наличие на реальном TS-Config локально не документировано)

Covox #FB (любой порт с A2 = 0) и #DD; SounDrive #0F + #1F — левый,
#4F + #5F — правый [UIO:855-873].

### General Sound / NeoGS

#BB команда/статус, #B3 данные, #33 управление; TS-BIOS сбрасывает NGS
`OUT (#33),#80`.

### OPL3 = ZXM-MoonSound (YMF278B, 33.8688 МГц; эмулируется как YMF262 + YMF278) [UMS]

| Порт | Назначение |
|---|---|
| #C4 | адрес банка 0 (чтение — статус) |
| #C5 | данные банка 0 |
| #C6 | адрес банка 1 / статус |
| #C7 | данные банка 1 |
| #7E/#7F | волновая часть OPL4 |

- Не декодируется, пока активны порты DOS [UIO:100-108].
- Инициализация по SO3S/SO3H: банк 1 рег #05 = 1 (NEW); банк 0 рег #01 = #20;
  затем обнулить B0–B8 / A0–A8 / C0–C8 / 20–35 / 60–75 / 80–95 / E0–F5,
  40–55 = #3F, BD = 0.
- **При NEW = 1 данные OPL2 требуют битов L/R в C0–C8** (иначе тишина), либо
  `b1 reg5 = 0`.
- Тайминги противоречивы: SO3H говорит, что задержка адрес→данные на 14 МГц
  не нужна; SISR переключается на 7 МГц на каждую запись. Даташита в REF нет.

### HUS (#80AF–#87AF)

Только в SH, в Unreal не реализовано — не проверено.

## 8. Накопитель (SD через Z-Controller) [UZC, TBB, TBF, FSD]

Порт **#77 запись** (Cfg; сброс 3):

| Бит | Смысл |
|---|---|
| 0 | во всём локальном коде всегда 1 |
| 1 | CS# SD1, активный низкий (`#01` — выбрана, `#03` — отпущена) |
| 2 | CS FT812 (VDAC2) |
| 3 | CS SD2, активный высокий (`%00001011`) |
| 4 | CS ESP32 / ZiFi32 |

- **#77 чтение:** Unreal возвращает 0. TS-FAT проверяет бит 1 перед записью
  и прерывает, если он стоит (вероятно, защита записи); FSD говорит бит 1 =
  карта вставлена. Проверить на железе.
- **#57:** запись — обмен байтом; чтение — возвращает байт **предыдущего**
  обмена и запускает новый с #FF (конвейер).
- **Чтение сектора DMA:** DMALen = 255, DMANum = 0, DMACtrl = #02, затем
  2x `IN (#57)` — сбросить CRC. Проверено по Verilog: DMA SPI→RAM на каждый
  байт запускает обмен с #FF и забирает `spi_dout` в момент запуска
  (`spi_stb = spi_start`), то есть байт **предыдущего** обмена — тот же
  конвейер, что у `IN (#57)` [`REF/fpga/common/dma.v` `spi_wrdata`,
  `REF/fpga/common/spi.v`, `REF/fpga/top.v`]. Поэтому после `IN`, вернувшего
  токен #FE, DMA сразу получает первый байт данных. Реализация — `sd_rdm` в
  `src/kernel/sd.s` (CMD18 + DMA на сектор, 13_sd_card.md).
- **Запись сектора:** токен через OUT, DMA #82, затем 2x #FF [TBF].
- Частота SPI в REF не документирована; Unreal тайминги SPI не моделирует.

## 9. Ввод

- **Клавиатура:** стандартная матрица `#xxFE` (A8–A15 — полуряды, биты 0–4
  активный низкий) [UIO:1347]; сырые скан-коды PS/2 set 2 через CMOS (§10).
- **Мышь Kempston** (декодируется при A5 = 0, A13 и A15 игнорируются):

| Порт | Содержимое |
|---|---|
| #FADF | кнопки: бит 0 L, бит 1 R, бит 2 M (активный низкий); биты 7:4 — счётчик колеса |
| #FBDF | X (8-бит счётчик) |
| #FFDF | Y (8-бит счётчик, растёт вверх) |

  Z88M меняет местами биты 0 и 1, ZXDNM отмечает, что у некоторых мышей L/R
  перепутаны — проверить на железе.
- **Джойстик Kempston:** остальные порты с A5 = 0 (#1F), активный высокий.
  В режиме DOS или при FDDVirt бит 7 порты #1F/#3F/#5F/#7F/#FF уходят в FDC.

## 10. RTC / NVRAM / прочее

**CMOS Gluk:** `#EFF7` бит 7 — включение CMOS (WC пишет #80/#00), `#DFF7` —
адрес, `#BFF7` — данные; на TSL декодируется полностью 16 бит; доступно и
при активном DOS.

| Регистр | Назначение |
|---|---|
| 0–9 | время и дата в BCD |
| #0B | WC пишет 0 |
| #0C | запись: бит 0 = 1 — очистить буфер PS/2; бит 1 — светодиод CapsLock |
| #F0 | запись 2 — режим буфера PS/2; далее чтение #BFF7 даёт скан-коды (0 — пусто, #FF — переполнение → очистить через #0C) |
| #B0–#E7 | настройки TS-BIOS с CRC — **не писать** |

VDAC2 / FT812 — на SPI #77 бит 2; при FT_EN строчный INT идёт от FT812.

## 11. Подводные камни (сводка)

1. Большинство регистров TS — только запись → теневые копии.
2. **Никогда не писать #7FFD** в родном коде (сбрасывает VPage).
3. **Алиасинг портов OPL3:** SISR пишет в порты OPL3 с B = #20 (A15 = 0),
   поэтому #C4/#C5 попадают под декодирование #7FFD в Unreal; у #C4 и #C6
   ещё и A0 = 0, что совпадает с декодом #FE. В Unreal это скрыто только тем,
   что обработчик MoonSound срабатывает первым; при `MoonSound=0` эти OUT
   переключили бы память и бордюр. **Проверить на железе; B ≥ #80 обходит
   алиас #7FFD.**
4. Регистры, защёлкиваемые по строке, задержки и правило перезагрузки GYOffs (§4).
5. Кэш не когерентен с DMA; запись SysConfig сбрасывает CacheConfig.
6. 14 МГц без кэша заметно медленнее из-за ожиданий (§2).
7. Кадровый INT теряется, если прерывания запрещены в момент прихода;
   LINE и DMA защёлкиваются; LINE срабатывает на всех 320 строках.
8. DMA по словам; прозрачность BLT1 — цвет 0; ASZ задаёт и размер пикселя,
   и шаг выравнивания.
9. VPage: для 256c — кратно 16 страницам, для 16c — 8; листы тайлов/спрайтов
   — кратно 8 (128 КБ).
10. Индексы TSU с младшим полубайтом 0 прозрачны; палитры спрайтов делят CRAM
    с картинкой 256c.
11. Запись в окно FMAddr идёт и в ОЗУ — после работы снимать FM_EN.
12. **Проверено на практике (2026-09-14): DMA игнорирует бит 0 адреса.**
    SDCC не выравнивает переменные — массив палитры или слово заливки по
    нечётному адресу DMA читает со сдвигом на байт (палитра перемешана,
    заливка полосами). В проекте все источники DMA в Win0/Win1 лежат в
    области `_DMABUF` с чётной базой (`src/kernel/dmabuf.s`).
13. Кэш прямого отображения индексируется `addr[8:0]`: код и горячие данные
    с одинаковыми младшими 9 битами адреса вытесняют друг друга. Замер:
    пустой цикл с кодом в Win0 и переменной в Win1 — 2752 итерации/кадр
    против 3044, когда код был в Win1, а данные в Win2.
