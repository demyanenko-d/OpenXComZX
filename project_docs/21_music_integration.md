# Музыка: куда в нашем коде ставить вызовы

План интеграции музыки в порт. **Что** играть где — разобрано в
[18_music_events.md](18_music_events.md) (геоскейп, базы, меню, заставки) и
[19_music_battle.md](19_music_battle.md) (бой). **Чем** играть — плеер на
кадровом прерывании, [20_music_player.md](20_music_player.md). Этот документ —
про третий слой: **где в наших исходниках стоят вызовы и как воспроизвести
семантику «музыка — это состояние»**.

Режимы звука — [11](11_sound.md), поток и `MUSIC.PAK` — [09 §7](09_converter.md),
ресурсы с карты — [13](13_sd_card.md), интерфейс — [08 §6](08_ui_port_plan.md).

Ссылки вида `файл:строка` — на наш код на момент написания (2026-09-19,
`839a510`).

## 1. Три слоя и что за что отвечает

| Слой | Где | Что знает | Аналог в OpenXcom |
|---|---|---|---|
| Вывод в чип | Win0, ассемблер (`_MUSIC`, `mus_isr`/`mus_out`, [20 §6](20_music_player.md)) | пары «регистр, значение» на кадр | `AdlibMusic::player` |
| Поток трека | банк 12 (`src/kernel/music.c`, [20 §9](20_music_player.md)) | `MUSIC.PAK`, кольцо, подкачка с SD, громкость, зацикливание; `mus_play(id)` — «тот же id не перезапускать» | `Music`, `Mix_PlayMusic` |
| **Группы и экраны** | тот же банк 12 (`mus_group`, таблица `mus_kind`) + событие `EVT_MUSIC` в ядре интерфейса | какие треки составляют `GMGEO`/`GMINTER`, что играет на каком экране | `Mod::playMusic`, `Mod::getRandomMusic`, `State::init` |

Третий слой — предмет этого документа. Он маленький (~300 байт кода и 3 байта
данных), но именно он даёт всё поведение оригинала.

### 1.1 Почему слой групп нужен отдельно от `mus_play`

`mus_play(id)` из [20 §11](20_music_player.md) уже не перезапускает **тот же
трек**. Оригинал же не перезапускает **ту же группу**: `Mod::playMusic`
запоминает не трек, а имя `name` (`REF/OpenXcom/src/Mod/Mod.cpp:527,549`), и
повторный `playMusic("GMGEO")` — no-op, хотя жребий мог бы выпасть на другой
трек. Без отдельного байта «какая группа играет» каждое закрытие окна над
геоскейпом перевыбирало бы тему — ровно та «мелочь», которая всё портит.

## 2. Минимальный интерфейс для игрового кода

```c
// src/kernel/music.c (банк 12), объявления — src/inc/game.h (рядом с opt)

#define MG_ONE    0     // «группа» — сам трек (как имя типа в _playingMusic)
#define MG_GEO    1     // GMGEO*: UFO 2 трека, TFTD 6
#define MG_INTER  2     // GMINTER*: UFO 1 трек, TFTD 4
#define MUS_ANY   0xFF  // жребий внутри группы (id == 0 у Mod::playMusic)

// Играть группу grp; type — точный тип (mus_ids.h) или MUS_ANY.
// Если grp уже «играет» — НИЧЕГО не делать (Mod.cpp:527).
void    mus_group(uint8_t grp, uint8_t type) __banked;
uint8_t mus_group_cur(void) __banked;        // что считается играющим (отладка, тесты)

// Роли, зависящие от игры (то, что в оригинале сидит в interfaces.rul / vars.rul
// и в коде): тип музыки для текущей игры по res_game().
#define MK_MENU       0   // GMSTORY  / GMWAITLO
#define MK_MEMORIAL   1   // GMLOSE   / GMDEBPOR   (soldierMemorial, commendationsLate)
#define MK_DEBR_GOOD  2   // GMMARS   / GMDEBGOO
#define MK_DEBR_BAD   3   // GMMARS   / GMDEBPOR
#define MK_TACTIC     4   // GMTACTIC / (нет — из террейна)
#define MK_BRIEF_DEF  5   // GMDEFEND / GMISPOSH  (умолчание BriefingData, AlienDeployment.h:49)
#define MK_LOSE       6   // GMLOSE   / GMLOSE
#define MK_WIN        7   // GMWIN    / GMWIN
uint8_t mus_kind(uint8_t k) __banked;
```

Всё. `mus_stop/pause/volume/playing/pump/fill/init` из
[20 §11](20_music_player.md) — движковые, игровой код их не трогает (кроме
окна опций и `boot.c`).

Удобные обёртки (макросы в `game.h`, без своего кода):

```c
#define mus_track(t)  mus_group(MG_ONE, (t))       // ровно этот тип
#define mus_role(k)   mus_group(MG_ONE, mus_kind(k))
```

### 2.1 Почему именно такая сигнатура

`mus_group(grp, type)` — это буквально `Mod::playMusic(name, id)`
(`Mod.cpp:525`): `grp` соответствует `name`, `type` — `id`. Два частных случая
оригинала ложатся без натяжек:

| Оригинал | У нас |
|---|---|
| `playMusic("GMGEO")` | `mus_group(MG_GEO, MUS_ANY)` |
| `playMusic("GMGEO", 1)` — **запоминается группа `GMGEO`**, но играет именно `GMGEO1` (`Mod.cpp:543,549`) | `mus_group(MG_GEO, MUS_GMGEO1)` |
| `playMusic("GMDEFEND")` — имя = единственный тип | `mus_group(MG_ONE, MUS_GMDEFEND)` |

Последняя строка важна: одиночные темы **не** получают своих `MG_*`. Иначе
сломается тонкость оригинала — в TFTD разбор с плохим счётом (`GMDEBPOR`) и
следом экран посмертных наград (`GMDEBPOR`) сравниваются по **имени типа** и
трек не перезапускается (`Mod.cpp:527`, [19 §5.2](19_music_battle.md)). При
`MG_DEBRIEF_BAD ≠ MG_MEMORIAL` мы бы дали лишний обрыв. Поэтому правило:

> **`MG_*` заводится только на настоящие многотрековые группы — `MG_GEO` и
> `MG_INTER`. Всё остальное — `MG_ONE` с номером типа.**

### 2.2 Состояние плеера групп

```c
static uint8_t mus_grp;     // MG_ONE / MG_GEO / MG_INTER — что «играет»
static uint8_t mus_typ;     // при MG_ONE — какой тип (иначе для отладки)
static uint16_t mus_rnd;    // отдельный ГСЧ жребия (см. §5)
```

Живёт в данных банка 12 (страница `#3B` всегда на месте, как и `mus_id` из
[20 §5.2](20_music_player.md)). **В `ST` не попадает**: в сейве музыки нет
(`18 §4.5`). Исключение на будущее — тема наземного боя: оригинал хранит её в
`SavedBattleGame::_music` (`REF/OpenXcom/src/Savegame/SavedBattleGame.cpp:473`),
у нас она ляжет в состояние боя, когда оно появится (§4.4).

Псевдокод:

```c
void mus_group(uint8_t grp, uint8_t type) __banked
{
    if (grp == mus_grp && (grp != MG_ONE || type == mus_typ)) return;  // Mod.cpp:527
    uint8_t t = type;
    if (t == MUS_ANY) t = mus_pick(grp);          // Mod::getRandomMusic
    if (t == MUS_NONE) return;                    // типа нет — играет прежнее (19 §7.3)
    mus_grp = grp;
    mus_typ = t;
    if (opt.music) mus_play(MUS_BASE + t, 1);     // 20 §11
}
```

Заметьте `return` при отсутствии типа — это `Mod.cpp:548-550`, где
`_playingMusic` не обновляется и продолжает играть прежнее. Полезно нам: в
сборке UFO вызов `GMTACWET` просто ничего не сделает.

## 3. Куда вешать вызов: три варианта и выбор

У нас нет `State::init()`. Есть `EVT_OPEN` (только при `do_push`,
`src/common/ui.c:716`), `EVT_CLOSE` (`ui.c:746`) и `EVT_TICK` (`ui.c:1046`).
Важнейшее отличие от OpenXcom:

> **`do_pop` (`src/common/ui.c:742-762`) не шлёт открывшемуся экрану ничего.**
> В OpenXcom `popState` сбрасывает `_init` (`Engine/Game.cpp:468`), и нижний
> экран заново прогоняет `init()` — а с ним и решение о музыке
> (`Engine/State.cpp:261-264`). Всё поведение «музыка возвращается сама»
> построено на этом.

### Вариант А — `mus_group()` в `EVT_OPEN` каждого экрана

- ✗ **Не восстанавливает музыку при закрытии окна.** Закрыли мемориал —
  `SCR_BASESCAPE` не получает `EVT_OPEN`, и `GMLOSE` играет дальше по базе.
  Пришлось бы вручную писать «вернуть музыку» в `EVT_CLOSE` каждого
  музыкального экрана и помнить, куда возвращаться.
- ✗ Экранов ~60, музыкальных из них 8 — шум в коде без пользы.
- ✓ Новых событий не нужно.

### Вариант Б — таблица «экран → группа» в диспетчере

- ✓ Вся карта музыки в одном месте, легко сверять с 18/19.
- ✗ Динамику не описывает: у `SCR_GEOSCAPE` группа зависит от
  `df_count`/`dz_state`/`ST->months`, у экранов боя — от правил развёртывания и
  террейна. Всё равно нужен обратный вызов в банк экрана.
- ✗ Таблица на 256 экранов или `switch` — в **резидентном** банке 1
  (`screens.c`), где места меньше всего.

### Вариант В — новое событие `EVT_MUSIC` (выбрано)

Ядро интерфейса шлёт верхнему экрану `EVT_MUSIC` после любой смены стека;
экран, у которого есть музыка, вызывает `mus_group(...)`; остальные не
обрабатывают событие и не делают **ничего**.

- ✓ Это **дословный перенос** `State::init()` + `Mod::playMusic`: то же место
  («экран стал верхним»), тот же результат («тот же — no-op»).
- ✓ Возврат из всплывающего окна восстанавливает музыку сам: `EVT_MUSIC`
  прилетит геоскейпу, тот скажет `mus_group(MG_GEO, MUS_ANY)`, и это будет
  no-op — трек **не перезапустится и не перевыберется** (`18 §4.1`).
- ✓ Динамика бесплатна: обработчик в банке экрана видит `ST`, `ctx`,
  `df_count`, правила.
- ✓ Молчащие экраны (подавляющее большинство) не пишут ни строки.
- ✗ Одно новое событие в протоколе и один вызов `scr_event` на смену экрана —
  копейки.
- ✗ Карта музыки размазана по банкам — лечится таблицей §4 в этом документе и
  комментарием-перечнем рядом с `EVT_MUSIC` в `src/inc/ui.h`.

**Выбран вариант В**, плюс явный `ui_music_check()` в двух местах геоскейпа, где
оригинал тоже зовёт музыку вне `init()` (§4.2).

### 3.1 Правки в ядре интерфейса

`src/inc/ui.h`, рядом с `EVT_ARROW` (строка 100):

```c
#define EVT_MUSIC 10  // экран стал верхним: поставить свою музыку (State::init + Mod::playMusic).
                      // Обработчик зовёт mus_group(); кто не обработал — музыку не трогает.
                      // Карта «экран -> группа» — project_docs/21_music_integration.md §4.
void ui_music_check(void) __banked;   // переспросить верхний экран (аналог повторного init())
```

`src/common/ui.c`, в `ui_run` сразу после `wait_frames(1)` (`ui.c:1009`):

```c
    wait_frames(1);
    mus_pump();                                   // 20 §8.2 — раз за оборот
    {   uint8_t top = stk[depth - 1];             // SDCC #15242: сравнение через локальную копию
        if (top != mus_scr) { mus_scr = top; scr_event(top, EVT_MUSIC, 0); } }
```

и рядом:

```c
void ui_music_check(void) __banked { if (depth) scr_event(stk[depth - 1], EVT_MUSIC, 0); }
```

`static uint8_t mus_scr;` — к `stk/depth` (`ui.c:37`), начальное значение 0
(нет экрана), поэтому первая проверка сработает всегда.

**Почему раз за оборот цикла, а не внутри `do_push`/`do_pop`.** `A_POP2`,
`A_POPN`, `A_POP_PUSH` (`ui.c:783-788`) делают несколько операций подряд.
Событие внутри `do_*` запускало бы музыку промежуточных экранов — а запуск
трека это чтение с SD и переинициализация чипа ([20 §11](20_music_player.md):
165 + ~125 пар). Проверка «верхний экран изменился» раз за оборот схлопывает
пачку в одну смену. Цена — музыка меняется кадром позже открытия экрана; это
даже к лучшему: экран уже нарисован, и пауза на чтение трека не мешается с
отрисовкой.

Проверка в начале оборота (а не в конце) важна ещё вот почему: после «новой
игры» `scr_menu.c:399-400` делает `A_SET SCR_GEOSCAPE` и **на следующем
обороте** `ui_request = SCR_BUILD_NEW_BASE`. Проверка в начале оборота застаёт
верхним `SCR_GEOSCAPE` и успевает поставить `GMGEO1` до того, как поверх ляжет
окно выбора места базы — ровно как в оригинале (`Menu/NewGameState.cpp:151`
зовёт `gs->init()` явно).

единственная дыра механизма «по смене экрана», и она закрывается именно здесь.

## 5. Жребий внутри группы и где хранится текущая группа

### 5.1 Состав групп

Конвертер таблицу групп не выдаёт (§6), поэтому на первом шаге — зашитая
таблица в `music.c`, по одному массиву на игру (`res_game()`: 1 — UFO, 2 —
TFTD):

| Группа | UFO | TFTD |
|---|---|---|
| `MG_GEO` | `GMGEO1`, `GMGEO2` | `GMGEO1`…`GMGEO6` |
| `MG_INTER` | `GMINTER` | `GMINTER0`, `GMINTER1`, `GMINTER2`, `GMINTER3` |

`GMGEO3..GMGEO10` и `GMTACTIC1..10` у UFO объявлены **без `catPos`**
(`18 §1.1`), ресурса для них нет — в таблицу не попадают. Это ровно то, что
делает `Mod::loadMusic`, отбрасывая незагруженные треки.

Итого таблица — 2 + 6 + 1 + 4 = 13 байт плюс индексы. Подстрочный поиск
оригинала (`Mod.cpp:504`) на Z80 не нужен и не воспроизводится.

### 5.2 Откуда брать случайное число

**Не из `rng_next()`** (`src/inc/game.h:267`): это ГСЧ кампании, его состояние
`ST->rng` (`src/inc/state.h:228`) попадает в сохранение. Если музыка будет
тянуть из него, одна и та же загрузка сейва пойдёт по разным веткам, и
автотесты `tests/*.oxs` перестанут быть воспроизводимыми.

Оригинал ровно этого и избегает: `Mod::getRandomMusic` берёт `RNG::seedless`
(`Mod.cpp:515`) — **отдельный генератор вне сида** (`18 §4.5`).

Наш аналог — свой 16-битный LCG в `music.c`, засеянный счётчиком кадров:

```c
static uint16_t mus_rnd;                       // seedless: не связан с ST->rng
static uint8_t mus_pick(uint8_t grp)           // Mod::getRandomMusic
{
    uint8_t n = grp_n[game][grp];
    if (!n) return MUS_NONE;
    if (mus_fixed) return grp_t[game][grp][ (uint8_t)(mus_fixed - 1) % n ];  // тесты
    mus_rnd = mus_rnd * 25173u + 13849u;       // тот же LCG, что в tools/, период 65536
    return grp_t[game][grp][ (uint8_t)(mus_rnd >> 8) % n ];
}
```

Засев — `mus_rnd = frames ^ 0xA5A5` в `mus_init()` (`frames` — глобал Win0,
`src/kernel/win0/crt0.s:233`): к моменту старта в нём уже несколько сотен
кадров загрузки, а к первой смене группы — тысячи.

**Для тестов** — `uint8_t mus_fixed;` в Win1 и `poke _mus_fixed <n+1>` в
сценарии (как `poke _alien_off 1`, CLAUDE.md): жребий становится
детерминированным, и сценарий может сверять номер играющего трека.

### 5.3 Где хранится текущая группа

`mus_grp` + `mus_typ` в данных банка 12 (§2.2). Не в `ST`, не в Win1 (Win1
заполнен, [20 §13.4](20_music_player.md)), не в сохранении.

При загрузке сейва музыка **не восстанавливается** — как в оригинале
(`18 §4.5`): `EVT_MUSIC` геоскейпа просто выберет новый трек `GMGEO`.

## 6. Чтобы не заикалось: загрузки, глобус, бой

Схема [20 §1](20_music_player.md) снимает основную проблему: **вывод в чип идёт
из кадрового прерывания и не зависит от того, чем занят главный цикл**. Остаётся
одно требование — чтобы в кольце всегда был задел.

| Наша долгая операция | Сколько кадров | Что делать |
|---|---|---|
| Перерисовка глобуса | до 28 (`scr_geo.c:915` — комментарий про догон тактов) | ничего: задел 96 кадров ≈ 2 с ([20 §8.1](20_music_player.md)) |
| Вращение/зум — перерисовки подряд | по 28 каждая, между ними оборот цикла | `mus_pump()` в `ui_run` дополняет кольцо между кадрами |
| Слайд заставки с SD | 5–9 (`13 §4`) | ничего |
| Картинка статьи Уфопедии с SD | 15–40 (`13 §6`) | ничего |
| **Первый запрос к SD**: `fat_mount` + открытие 7 пакетов + чтение каталогов | самая долгая операция в игре | `mus_fill()` в циклах `src/kernel/sdres.c:55` и `:81` — между пакетами |
| Загрузка карты боя и тайлсета (`scr_battle.c`, `EVT_OPEN`) | десятки кадров | `mus_fill()` между ресурсами, как велит [20 §8.3](20_music_player.md) |
| Построение вида боя, дисплей-лист, полоса скролла | 4 (после оптимизаций, коммиты `40d42ce`…`839a510`) | ничего |
| Отрисовка окна, восстановление фона | единицы кадров | ничего |

Правило простое: **`mus_pump()` — один раз за оборот `ui_run` (§3.1),
`mus_fill()` — внутри всего, что за один вызов может съесть больше ~50 кадров**
(загрузчики ресурсов). `mus_fill()` без SD, возвращается сразу, если кольцо
полно.

### 6.1 Сплит-экран боя — особый случай

`isr_frame` (`src/kernel/win0/crt0.s:170-215`) при включённом сплите
(`scr_battle.c:100-112`) приходит **дважды за кадр**: фаза 0 на строке разреза,
фаза 1 в гашении. Музыку выводить **только в фазе 1**, то есть в ветке
`frame_work` (`crt0.s:196`), иначе темп удвоится, а подогнанная задержка `djnz`
в фазе 0 (`crt0.s:197` `split_wait`) поедет. Это же записано в
[20 §13.5](20_music_player.md); здесь — точное место врезки: сразу после
`call nz, input_isr` (`crt0.s:207`), до возврата смещений карты.

### 6.2 Чего трогать не надо

- **Игровая пауза геоскейпа** (`ST->speed = 0`) музыки не касается (`18 §1.4`).
- **Развёрнутое окно воздушного боя** останавливает время — музыка играет
  дальше.
- **Отдаление камеры** (`DZ_OUT`) — музыка меняется в его конце, а не в начале
  (`18 §2.2`).
- Тишины в геоскейпе не бывает вообще (`18 §4.4`): все треки зациклены, пауз
  нет.

## 9. Открытые вопросы

1. **Зацикливать ли `GMWIN`/`GMLOSE`/`GMSTORY`.** В ADLIB они зациклены
   данными, OpenXcom для цифровых форматов просит `loop = 0` (`Mod.cpp:531`).
   Повторяем DOS или замысел OpenXcom? (тот же вопрос — `18 §6.1`).
2. **Где держать таблицу групп** — зашитой в `music.c` (§5.1) или отдельной
   записью в `RULES.PAK`, чтобы мод мог менять. Сейчас предложено первое;
   переезд дешёвый.
3. **Момент `GMLOSE` при поражении по месяцу.** У нас отчёт и «You have
   failed» — два экрана (`scr_geo.c:972,976`), в оригинале это один
   `MonthlyReportState` (`:305-316`). Проверить по исходнику, звучит ли `GMLOSE`
   до нажатия OK; если да — обработчик нужен на `SCR_MONTHLY_REPORT` при
   `RF_GAME_OVER`, а не на `SCR_REPORT_FAILED`.
4. **`EVT_MUSIC` при `A_POPN`.** Выбрана проверка раз за оборот цикла (§3.1);
   если когда-нибудь понадобится сменить музыку строго в момент операции со
   стеком — вызывать `ui_music_check()` явно, как в геоскейпе.
5. **Загрузка сейва законченной кампании.** Оригинал открывает
   `StatisticsState` и оставляет музыку меню (`18 §2.1`); у нас
   `scr_menu.c:419` всегда идёт в геоскейп. Отдельная недоделка, но музыку
   затрагивает — записать в `14_todo.md`.
6. **Тема боя в сохранении.** Когда появится сохранение боя — хранить **тип**
   музыки, как `SavedBattleGame::_music` (`19 §2.3`), иначе при загрузке боя
   тема сменится.
7. **`opt.music = 0` на ходу.** Предложено: `mus_group` продолжает вести
   `mus_grp`/`mus_typ`, но не зовёт `mus_play`; при включении музыки в
   опциях — `mus_play` записанного типа. Сверить с окном опций, когда оно
   получит настройку музыки.
8. **Щелчок при смене группы.** `Music::play` — это обрыв без затухания
   (`18 §4.2`); на OPL3 нужен ли key-off перед стартом (`18 §6.9`,
   [20 §11](20_music_player.md) — `mus_stop` это уже делает).
9. **Ambience-канал боя** (зацикленный SFX террейна, TFTD № 67) идёт
   параллельно музыке весь бой (`19 §8.9`) — в режимах 2–4 отбирает канал.
   Решается вместе с эффектами, не здесь.
