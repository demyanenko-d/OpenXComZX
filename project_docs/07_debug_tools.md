# Отладка: сборка, запуск, сценарии, тестовый режим эмулятора

## 1. Быстрый старт

```
powershell -File tools\build.ps1                                        # сборка -> tmp\build\oxz.spg
powershell -File tools\run.ps1                                          # запуск в окне (руками)
run.cmd                                                                 # только окно игры, без консоли (для записи Win+G); с аргументами — как run.ps1, с консолью
powershell -File tools\run.ps1 -Script tests\selftest.oxs -Headless     # самотест банков/страниц
powershell -File tools\run.ps1 -Script tests\ui_geoscape.oxs -Headless  # автотест интерфейса
powershell -File tools\run.ps1 -Script tests\ui_geoscape.oxs            # то же в окне, затем руками
powershell -File tools\run.ps1 -Frames 300 -Shot tmp\shots\x.png        # N кадров, снимок, выход
```

Все артефакты — в `tmp/` (правило проекта): сборка в `tmp/build`, снимки
в `tmp/shots` (снимки автотеста интерфейса — отдельно, `tmp/shots/ui/`),
ini эмулятора `tmp/build/oxz.ini`, метки `tmp/build/oxz.labels`.

## 2. Конвейер сборки (`tools/build.ps1`)

Раскладка памяти — 08 §4.

1. Конвертер `OxzConv` пересобирается, если его исходники новее exe; данные
   игры (`tmp/sd/OXZ/<игра>`) конвертируются из `Steam\`, если их нет или
   конвертер новее; `OxzConv headers` → `tmp/build/gen/*.h`.
2. Генерация `tmp/build/banks.s` (таблица «банк → страница») и `packs.s`
   (страницы пакетов данных, вшиваемых в SPG с #50).
3. `sdasz80` — `src/kernel/crt0.s` (первым: задаёт порядок областей),
   `bank.s`, `dmaq.s`, `dmabuf.s`, `glyph.s`, `banks.s`, `packs.s`.
4. `sdcc -c` — общие C-модули (`--sdcccall 1 --opt-code-size --std-sdcc11
   --debug`) и банковые (`--codeseg BANKn --constseg BANKn`).
   `--debug` код не меняет (размеры областей проверены), даёт `oxz.cdb`.
5. **`tools/checkasm.js`** — поиск в `.asm` ошибки кодогенерации SDCC 4.5
   (§7): сборка падает, если место найдено.
6. Линковка: `--code-loc 0x0100 --data-loc 0x4000 -Wl-b_DMABUF=0x7C00
   -Wl-b_BANKn=0xn8000 --debug` → `oxz.ihx`, `oxz.map`, `oxz.noi`, `oxz.cdb`.
7. `tools/checkmap.js` — границы областей и пересечения (sdld молча
   накладывает секции; ловил ошибку порядка областей).
8. `tools/mkspg.js` — Intel HEX (с записями типа 04) → SPG 1.0: занятые
   512-байтные секторы группируются в блоки по страницам (окно 0 → #04,
   окно 1 → #05, банк N → по `--bank`, пакеты — `--data PP:файл`).
   PC = заглушка `#7FE0`.
9. `tools/mklabels.js` — `.noi` (глобальные символы) + `.cdb` (статические
   функции, имя `модуль$функция`) → метки `PP:AAAA имя`.

## 3. Запуск (`tools/run.ps1`)

- Генерирует `tmp/build/oxz.ini` из `unreal/build/oxz/Unreal.ini`
  (`tools/mkini.js`): `AUTOLOAD.diskA=` (пусто), `AUTOLOAD.snapshot=` → наш
  SPG, `ZC.SDCARD=` → `wc.img` эмулятора.
- Запускает `unreal/build/oxz/Unreal.exe -c ini -l labels [...]` **из корня
  проекта** — относительные пути в сценариях считаются от него.
- Код выхода: код программы (порт #FAAF) или сценария (`exit`); **#FD** —
  не прошёл `expect`/не найдена метка, **#FE** — таймаут `waitmark`,
  **#EE** — авария программы (RST 0 / переход на #0000).

## 4. Тестовый режим эмулятора (наша доработка `unreal/`)

Файлы: `unreal/Unreal/app/oxz_test.{h,cpp}` + хуки в `app/emul.cpp`,
`app/mainloop.cpp`, `devices/io/io.cpp`, `input/input.cpp`,
`platform/video.cpp`, `machine/zx_machine.h` (профилировщик),
`CMakeLists.txt`. Исправлена ошибка эмулятора: `app/getopt.cpp` начинал
разбор с `argv[0]` (`optind = 0`) — ключи командной строки не работали вообще.

| Ключ | Действие |
|---|---|
| `-t N` | выйти после N кадров |
| `-o файл.png` | снимок активной области при выходе |
| `-s сценарий` | выполнить сценарий |
| `-H` | без окна (консольный режим) |
| `-c`, `-l`, `-b` | штатные: ini, метки, точки останова |

С `-t`/`-o`/`-H` — звук выключен, эмуляция без паузы до 50 Гц (быстрее
реального времени). Со сценарием без них — обычное окно: сценарий
отрабатывает, затем управление у пользователя.

### Отладочные порты (в программе — `src/inc/tsconf.h`)

| Порт | Имя в C | Действие |
|---|---|---|
| #F8AF | `OXZ_DBG_CHAR` | символ в stdout эмулятора |
| #F9AF | `OXZ_DBG_HEX` | байт как hex |
| #FAAF | `OXZ_DBG_EXIT` | выход с кодом (в конце кадра) |
| #FBAF | `OXZ_DBG_SHOT` | снимок `<-o>_NNN.png` (по умолчанию `tmp/shots/oxz_shot_NNN.png`) |
| #FCAF | `OXZ_DBG_MARK` | метка для `waitmark` в сценарии |
| #FDAF, #FEAF | `OXZ_BIOS_LO/HI` | адрес блока запроса службы «BIOS» (Win1) |
| #FFAF | `OXZ_BIOS_CMD` | команда службы: 1 записать, 2 прочитать, 3 размер, 4 удалить файл слота |
| #FDAF (чтение) | `OXZ_DBG_SCRIPT` | #5A (`OXZ_SCRIPT_SIG`), если эмулятор выполняет сценарий (`-s`); иначе обычное чтение |

Номера регистров #F8–#FF в TS-Config не заняты: на реальном железе запись
игнорируется, в коде игры порты можно оставлять.

**Под сценарием** (чтение #FDAF = #5A, 2026-09-15; `devices/io/io.cpp`) игра: не
показывает интро при запуске (сразу главное меню, `src/kernel/boot.c`) и берёт
**постоянное зерно ГСЧ** новой игры (`0x9E3779B9`, `src/game/newgame.c`), а не зерно от
кадра — исходы случайностей в тестах больше не зависят от тайминга загрузки и окон.
Нужен другой исход — `pokew 06:0032 <зерно>` (поле `state_t.rng`) перед нужным местом
(так сделано в `tests/dogfight.oxs`). Без сценария (`-t`/`-o`, окно) — всё как на железе.

**Служба «BIOS» — файлы сохранений** (`src/kernel/bios.c`,
`oxz_test.cpp: bios_call`): программа кладёт в Win1 блок `cmd, status, slot,
game, page, pad, offs, len, result`, пишет его адрес и команду в порты;
эмулятор выполняет команду с физической памятью (страница:смещение), пишет
`status` (0 — успех, 1 — нет файла) и `result` и сбрасывает кэш. Файлы —
`tmp/saves/<UFO|TFTD>/SLOTnn.SAV` от корня проекта. Если порты молчат
(железо), `status` остаётся #FF — игра хранит слоты в страницах пула
(12 §3.1).

Интерфейс (`src/ui/ui.c`) после каждой обработки ввода/запроса пишет в
#FCAF номер верхнего экрана (перед обработкой — 0), а в консоль — строку
`ui: screen N, K frames` (кадров на обработку и перерисовку) — готовые
замеры скорости по каждому окну.

Ещё правки эмулятора (2026-09-14):
- stdout без буферизации (`setvbuf` в `app/emul.cpp`) — отчёт теста не
  теряется при зависании или принудительной остановке;
- **убрана привязка главного потока к ядру 0** (`SetThreadAffinityMask(…, 1)`
  в `app/emul.cpp`): при занятом ядре 0 (у пользователя — процессы
  `pc_player.exe` другой сессии с приоритетом RealTime) эмулятор не получал
  процессор и «висел» с нулевой загрузкой;
- `shot` создаёт каталог снимка и снимает **через 2 кадра** после команды
  (§7: готовый кадр не содержит того, что записано после прохода луча);
- `poke`/`pokew` **сбрасывают кэш TS-Config** (`invalidate_ts_cache()`):
  иначе программа с включённым кэшем окна читает старое значение и пишет
  его обратно (так «не срабатывал» `pokew _cursor_x`);
- **профилировщик** (команды `profile on/off`);
- **мышь Kempston в окне** (`input/input.cpp`): SDL-версия `readmouse`
  отдаёт смещение за кадр, а код от DirectInput брал его как абсолютную ось —
  порт Kempston показывал смещение, курсор дёргался на месте. Теперь
  счётчики копятся (пара `msx_prev/msx` держится около 0..255, интерполяция
  внутри кадра — через разность). Мышь захватывается левым кликом в окне,
  отпускается `Shift+Esc` (`main.lockmouse`); скорость — `MouseScale` в ini.
- Запуск без сценария/кадров/снимка (`run.ps1` без ключей) пишет в ini
  `MISC.HideConsole=1` — эмулятор закрывает свою консоль (`FreeConsole`), а
  `run.cmd` без аргументов стартует PowerShell скрытым: на экране только окно
  игры, и Xbox Game Bar (Win+G) записывает его. Вывод в консоль (`ui: screen`)
  в этом режиме не виден.

## 5. Сценарии (`tests/*.oxs`)

Одна команда в строке, `#` — комментарий. Выполняются на границах кадров.

| Команда | Действие |
|---|---|
| `wait N` | ждать N кадров |
| `key K [N]` | нажать клавишу ZX, держать N кадров (3), отпустить, пауза 3; с CAPS SHIFT — `key CS+5` (стрелки ZX CS+5..8 → `KEY_LEFT…KEY_RIGHT`) |
| `down K` / `up K` | нажать / отпустить (держится между командами) |
| `type ТЕКСТ` | набрать текст (по 3 кадра нажатие/отпускание) |
| `mouse X Y` | счётчики мыши Kempston (0–255) |
| `move DX DY [N]` | плавно сдвинуть счётчики за N кадров (DY > 0 — вверх) |
| `click [L\|R\|M] [N]` | нажать кнопку мыши на N кадров (3), отпустить, пауза 3 |
| `press B` / `release B` | держать / отпустить кнопку |
| `poke A V`, `pokew A V` | записать байт / слово (кэш сбрасывается) |
| `peek A [N]` | вывести N байт |
| `expect A V`, `expectw A V` | проверить байт / слово, иначе выход с #FD |
| `waitmark N [таймаут]` | ждать, пока программа запишет N в #FCAF (иначе #FE) |
| `shot файл.png` | снимок активной области (через 2 кадра; каталог создаётся) |
| `profile on` / `profile off [N]` | профилировщик: начать / отчёт (N строк, 30) |
| `echo ТЕКСТ` | вывести в консоль |
| `exit [код]` | выйти |
| `end` | закончить сценарий, дальше — пользователь |

Клавиши: `A`–`Z`, `0`–`9`, `ENTER`, `SPACE`, `CS`/`CAPS`, `SS`/`SYM`,
сочетания через `+` (`CS+5`), псевдонимы `LEFT`/`DOWN`/`UP`/`RIGHT`
(CS+5..8), `DELETE` (CS+0), `BREAK` (CS+SPACE), `EDIT` (CS+1).
В игре: `SPACE` (и `BREAK`) — ESC (отмена), `ENTER` — OK, буквы и цифры —
горячие клавиши окон (`src/kernel/input.c`).

Адрес `A`: **имя метки** (глобальный символ C/asm из `oxz.labels`, например
`_cursor_x`), `PP:AAAA` — физическая страница:смещение, или число — адрес
CPU по текущим окнам; к любому можно добавить смещение: `_pg_test+2`.
Статические (`static`) переменные C в метки не попадают — то, что
проверяет сценарий, делать глобальным.

**Приём «курсор напрямую»:** драйвер мыши держит абсолютный курсор в
глобальных `cursor_x`/`cursor_y` — сценарий ставит его точно в экранные
координаты (`pokew _cursor_x 100`), минуя счётчики Kempston. Идея
пользователя: сервисы игры живут в «BIOS» (страница ядра), эмулятор знает
их адреса по меткам и может подменять состояние/ответы.

**Открыть любое окно:** `poke _ui_request <номер>` (номера —
`src/ui/screens.h`) — интерфейс откроет экран поверх текущего.

Пока сценарий активен, мышь Kempston задаёт он (хост-мышь не читается);
клавиши сценария накладываются поверх клавиатуры хоста.

### Типовой шаг — клик и ожидание окна

```
pokew _cursor_x 288             # курсор на кнопку INTERCEPT
pokew _cursor_y 5
click L
waitmark 33 300                 # окно перехвата нарисовано
shot tmp/shots/ui/05_intercept.png
key SPACE                       # ESC -> Cancel
waitmark 32 300                 # снова геоскейп
```

Нажатия кнопок мыши и клавиш программа защёлкивает в кадровом прерывании
(`input_isr`), поэтому клик не теряется, даже если перерисовка длится
дольше удержания кнопки (3 кадра).

Раскладка времени рендера глобуса по зумам: `powershell -File tools\globeprof.ps1
[-Zooms 0,1,2] [-Out tmp\globeprof.md]` — для каждого зума сценарий «новая игра → зум →
профиль одного поворота», функции сводятся в группы (проекция, таблицы, многоугольник,
рёбра, питатель DMA, ячейки на C), таблица кадров. Внутренние метки асм-модулей для
профиля делаются глобальными (`.globl`) — иначе время уходит в ближайшую глобальную метку.
Скрипты `tools/*.ps1` читает PowerShell 5.1 без BOM как ANSI: строки вывода в них —
латиницей (комментарии можно по-русски).

Все сценарии запускаются с образом SD-карты `tmp/sdimg/oxz.img` (собирает
`tools/build.ps1`, подключает `tools/run.ps1` через `ZC.SDCARD`,
13_sd_card.md §5). Эмулятор — с `TS_VDAC=5BIT` (02 §4: палитра с битом 15).

## 6. Профилировщик

`profile on` обнуляет счётчики и включает учёт: перед каждой инструкцией
запоминается адрес в памяти эмулятора (страница + смещение, то есть с
учётом банков), после — такты инструкции. `profile off [N]` выключает и
печатает N самых дорогих функций: такты относятся к ближайшей метке снизу
в той же странице (`oxz.labels`: глобальные символы + статические функции
`модуль$функция` из `oxz.cdb`). Такты — в единицах кадра 3.5 МГц
(71680 на кадр), то есть «кадров» в отчёте — реальное время.

```
profile on
key F
waitmark 39 300
profile off 20
```
```

OXZ: prof  19.6%     603764  _glyph_run
OXZ: prof  12.3%     378208  text$draw_glyph
OXZ: prof   9.2%     282881  _gfx_fill
...
```

## 7. Подводные камни

- Windows PowerShell 5.1 читает UTF-8 без BOM как ANSI: **не править
  текстовые файлы через `Get-Content`/`Set-Content`** — портится кириллица.
- Сборка эмулятора — только `-j 2` и Debug (см. 01).
- `-o` и `shot` без каталога пишут относительно корня проекта — давать пути
  в `tmp/`.
- **Снимок отстаёт от программы.** Эмулятор снимает последний готовый кадр;
  запись в строки экрана выше луча попадает только в следующий кадр. Метка
  `waitmark` пишется сразу после рисования, и снимок «сразу» терял последний
  глиф текста. Поэтому `shot` ждёт 2 кадра.
- **Кэш и запись мимо CPU.** Кэш TS-Config не видит записей DMA и отладчика;
  `poke` эмулятора теперь сбрасывает кэш. В программе: DMA не должен писать
  в страницы, стоящие в кэшируемых окнах (02 §2).
- **Ошибка SDCC 4.5.0 #15242**: `if (k == g) …; g = k;` при `k` в A и `g` в
  памяти компилируется в `sub a,(hl)` — A портится, а дальше используется как
  `k`. Обход — сравнивать с локальной копией (`uint8_t p = g; if (k == p)`).
  `tools/checkasm.js` ищет такие места при каждой сборке (01, «Ошибка
  кодогенерации SDCC»).
- **Ошибка библиотеки SDCC 4.5.0 `__mulsint2slong`**: знак по младшему байту,
  `(int32_t)a * b` неверно при младшем байте ≥ #80. Своя замена —
  `src/kernel/mul32.s` (в `oxz.map` символ должен быть из модуля `mul32`).
- **SDCC 4.5 падает** на литеральном указателе на структуру с полем-массивом
  и константным индексом (`((state_t *)0xC000)->base[0]`) — объявлять
  переменную `__at(адрес)` (12 §2).
- `end` в сценарии с `-Headless` оставляет эмулятор работать без окна —
  в автотестах завершать `exit`.
- Стартовые значения кампании зависят от ГСЧ (зерно — номер кадра): при
  изменении скорости кода они меняются. Проверять разницы, а базу задавать
  `poke` (как `tests/campaign.oxs`).
