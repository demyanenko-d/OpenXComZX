# SD-карта: драйвер, FAT, ресурсы с карты

Сделано 2026-09-15. Игра читает большие пакеты данных прямо с SD-карты
(Z-Controller), а не только из SPG: картинки Уфопедии (TFTD — 7 МБ), фоны окон,
предметы. Код — банк 12 (`#3B`).

## 1. Слои

| Файл | Что |
|---|---|
| `src/kernel/sd.s` | драйвер карты (область `_BANK12`): `sd_init`, `sd_rd` (сектор в буфер CPU, `INIR`), `sd_rdm` (N секторов подряд CMD18, каждый — DMA SPI→RAM), `sd_wr` (CMD24) |
| `src/kernel/fat.c`, `src/inc/fat.h` | FAT16/FAT32 только для чтения + запись на месте: `fat_mount`, `fat_open`, `fat_read`, `fat_write` |
| `src/kernel/sdres.c` | ресурсы с SD: пакеты `OXZ/<UFO\|TFTD>/{BACK,UFOP,ITEMS}.PAK`, кэш слотов |
| `src/kernel/res.c` | `res_find`: сначала вшитые пакеты (SPG), потом `sdres_find` |

## 2. Драйвер (`sd.s`)

Порты Z-Controller — 02 §8. Последовательности команд — по
`REF/frontend/z80_fw/sd.s`, TS-BIOS (`REF/tsbios/src/booter.asm`,
`pff/diskio.c`) и FatFs.

- Инициализация: 500 холостых тактов с CS#=1, CMD0 до R1 = #01, CMD8 (#1AA:
  SDv2, иначе SDv1), ACMD41 (с HCS для v2) до R1 = 0, CMD58 — бит CCS (блочная
  адресация SDHC/SDXC), для байтовой — CMD16 (512). Тип — `_sd_type`.
- Параметры — в глобальных переменных (`_sd_lba`, `_sd_ptr`, `_sd_phys`,
  `_sd_cnt`), результат — A (0 — успех).
- `sd_rdm`: CMD18, для каждого сектора — ждать токен #FE, DMA
  (`DMALen=255, DMANum=0, DMACtrl=#02`, приёмник — физический адрес
  `_sd_phys`, регистры напрямую с опросом `DMAStatus`, как `gfx.c`/`far.c`),
  2 байта CRC; затем CMD12 **без переключения CS** с пропуском байта-заполнителя
  и ожиданием, пока карта занята (R1b). Конвейер порта #57 у DMA тот же, что у
  `IN` — сверено по Verilog (02 §8).
- DMA пишет по физическому адресу и без ALGN переходит через границы страниц
  (02 §6) — окна CPU не нужны, сектор идёт прямо в страницу пула.
- Очередь `dmaq` (прерывание DMA) в проекте не запущена: графика и
  `far_copy` работают с DMA напрямую. Первая версия `sd_rdm` через
  `dmaq_push`/`dmaq_wait` зависала в `dmaq_wait` (профилировщик: 99 %).

## 3. FAT (`fat.c`)

- Том: MBR (первый раздел типа 4/6/B/C/E) или загрузочный сектор в секторе 0.
  Только 512 байт на сектор; имена 8.3 (`OXZ/TFTD/UFOP.PAK`).
- `fat_open` сворачивает цепочку кластеров в **участки подряд идущих кластеров**
  (`FAT_RUNS` = 8; больше — `FAT_FRAG`, файл надо переписать на карту заново).
  Проход по цепочке: запись `c → c+1` внутри уже загруженного сектора FAT
  проверяется циклом по 16-битным словам (`chain_skip`) без вызова `fat_next`.
- `fat_read(f, pos, far_t dst, len)`: целые секторы с чётного `dst` —
  `sd_rdm` на весь остаток участка (одна команда CMD18); края и нечётный
  приёмник — через `secbuf` (Win1) и `far_write`.
- `fat_write`: целые секторы на место (файл уже нужного размера) — для будущих
  слотов сохранений на карте.

## 4. Ресурсы с карты (`sdres.c`)

| Пакет | Что | TFTD | UFO |
|---|---|---|---|
| `BACK.PAK` | фоны окон `BACKnn.SCR` | 14, 0.9 МБ | 17, 1.0 МБ |
| `UFOP.PAK` | картинки статей `UP*.SPK/BDY`, `UP_BORD*` | 113, 7.0 МБ | 46, 2.8 МБ |
| `ITEMS.PAK` | `BIGOBS`, куклы брони `MAN_*.SPK` | 35, 2.0 МБ | 21, 1.2 МБ |
| `CUTS.PAK` | слайды заставок (с 2026-09-15) | 44, 2.8 МБ | 7, 0.44 МБ |

Слайд заставки (64 000 байт) грузится с карты в эмуляторе за 5–9 кадров.

- При первом запросе ресурса, которого нет во вшитых пакетах: `fat_mount`,
  открыть четыре пакета, их каталоги — в одну страницу пула (по 4 КБ на пакет, до
  255 ресурсов). Нет карты или файлов — `sd_state = 2`, ресурс «не найден»
  (фон не рисуется).
- **Кэш: 6 слотов по 4 страницы (64 КБ — картинка 320x200)** из пула. Слот
  ищется сначала по номеру ресурса (без обхода каталога); новый ресурс
  занимает пустой или давно не запрошенный слот. Кэш нужен потому, что фон
  окна перерисовывается из ресурса на каждом `restore` (`ui.c`) и при
  возврате к нижнему окну.
- Пул: шрифты 1 + каталоги 1 + слоты 24 + сохранения без BIOS до 20 = 46 из 64
  страниц.
- Фоны на карте освободили 0.9–1.1 МБ страниц #50–#AF: UFO теперь влезает
  (#50–#6D, до этого 97 страниц при 96 — сборка UFO не шла).

## 5. Образ для эмулятора

`tools/build.ps1` собирает `tmp/sdimg/oxz.img` (64 МБ, без таблицы разделов,
**кластер 4 КБ → FAT16**) утилитой `unreal/tools/robimg/robimg.exe`
(`-p=<образ> -s=65536 -o=4096`, затем `-a=1 -C=<tmp\sd>`; пути — абсолютные,
иначе «Error argument format»). Образ пересобирается, когда пакеты новее.
Кладутся данные обеих игр из `tmp/sd`. `tools/run.ps1` подключает образ
(`ZC.SDCARD`). До 2026-09-15 образ был FAT32 с кластером 512 байт — ветка FAT32
проверена на нём.

## 6. Скорость (эмулятор, 14 МГц)

| Шаг | Было | Стало | Что сделано |
|---|---|---|---|
| Старт до главного меню (монтирование, 3 каталога, фон) | 151 кадр | 47 (кластер 512 Б), 14 (кластер 4 КБ) | `chain_skip` вместо `fat_next` на каждый кластер (профиль: `fat_next` + `fat_open` — 80 %); образ с кластером 4 КБ |
| Статья Уфопедии (фон + картинка + предмет) | 30–165 кадров | 15–40 | DMA CMD18 вместо `INIR` по сектору, кэш слотов |

На железе скорость упирается в частоту SPI (в REF не документирована, 02 §8);
по оценке пользователя DMA даёт почти 1 МБ/с.
