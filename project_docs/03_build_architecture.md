# Архитектура программ под TS-Config: сборка, память, форматы

Сокращения: **R** = `REF/`, **SS** = `D:\ProjectWork\SoundSinth` (соседний
проект пользователя, там лежат недостающие скрипты сборки). WC = Wild
Commander. Win0–Win3 — окна процессора #0000/#4000/#8000/#C000. Порты
страниц — #10AF–#13AF.

## Итоговая рекомендация

**Игра — отдельная программа в формате SPG**, собранная тем же конвейером
SDCC 4.5 + sdasz80 + Node, **со своим драйвером SD/FAT32**, без WC во время
работы. WC остаётся запускалкой (Enter на `.SPG` или пункт в `WC.MNU`) и
средой разработки.

Почему не плагин WC:
- гарантирован только #8000–#BFFF под код; #4000–#7FFF — владения WC;
- #0000 затирают FindNext и GEDPL;
- с плагином грузится максимум 96 КБ, все плагины делят 64 страницы;
- нет seek; вызовы WC API сбрасывают Win3;
- проблемы кэша/DMA, нужно обслуживать прерывание WC.

Почему не TR-DOS `$C`: ~40 КБ с #6000, пейджинг 128K через #7FFD. Максимум —
загрузочная заглушка.

## 1. `R/src_sdcc` — «VGM Player OPL3 v2.0», плагин WC (VGMPLAY.WMF)

Играет VGM/VGZ на OPL1/2/3, AY/YM2149/YM2203, SAA1099 (`R/src_sdcc/main.c:1-18`).

### Инструменты и флаги

- SDCC 4.5.0 #15242. Флаги: `-mz80 --sdcccall 1 --no-std-crt0
  --opt-code-size --disable-warning 85`; ассемблер `sdasz80 -plosff`
  (`R/src_sdcc/build.bat:28-31`).
- **sjasmplus** нужен для отдельных страниц-блобов. `build.bat` ищет его в
  `..\tools\sjasm\` (в REF нет); копия есть в
  `D:\ProjectWork\vdos\introspec\_bin\sjasmplus.exe`.
- Node-скрипты: `R/src_sdcc/scripts/gen_pos_table.js`,
  `gen_freq_tables.js`, `ihx2wmf.js`.
- `sdar` собирает библиотеку, где каждая функция WC — отдельный `.rel`
  (линкуется только используемое) — `R/src_sdcc/lib/wc_api/build_lib.bat`.
- `robimg.exe` собирает FAT-образ; в REF нет, лежит в `SS/scripts/robimg.exe`.

### Шаги сборки (`R/src_sdcc/build.bat:39-159`)

1. Генерация `asm/pos_table.s` и частотных таблиц (`build/freq_tables.bin`,
   `inc/freq_lut_map.h`).
2. `inflate.asm` — sjasmplus, добивка до 16384 байт; `cmdblocks.asm`.
3. Компиляция `main.c`, `lib/vgm.c`, `lib/keys.c`.
4. Ассемблирование `crt0`, `isr`, `pos_table`, `txtlib`, `inflate_call`, `spectrum`.
5. Линковка `sdcc --code-loc 0x8000 --data-loc %DATA_LOC%`, `crt0.rel` первым.
6. **PowerShell-проверка `.map`: сборка падает, если CODE налезает на DATA
   или что-то доходит до #C000.** (sdld молча накладывает секции —
   проверка обязательна, см. также `SS/scripts/build_z80fw.bat:96-114`.)
7. Склейка трёх блобов `copy /b` → `extra_combined.bin`.
8. `node ihx2wmf.js … --extra extra_combined.bin` → WMF.
9. `robimg -p=..\tsconf.img -s=280000 -C=..\DiskRef` → образ диска.

Неиспользуемые файлы: `R/src_sdcc/vgmplayer.lk` (устарел, реальный —
`build/vgmplay.lk`); `asm/opl3.s` и `asm/wc_api.s` в текущей сборке не
линкуются.

### Раскладка памяти

Весь C-код и данные — в одном окне #8000–#BFFF (страница плагина 0).
Реальная карта (`R/src_sdcc/build/vgmplay.map`):

| Секция | Начало | Размер / конец |
|---|---|---|
| `_CODE` | 0x8000 | 13 884 байта |
| `_DATA` | 0xB700 | 1751 байт |
| `_GSINIT` | 0xBDD7 | |
| `_HOME` | 0xBE11 | |
| `_INITIALIZER` | | до 0xBF7F |

Свободно ~128 байт до #C000. SP не ставится — работает на стеке WC.

Шесть страниц плагина по 16 КБ, каждая подключается по-своему:

| Стр. WMF | Содержимое | Как подключается |
|---|---|---|
| 0 | код | Win2 |
| 1–3 | частотные таблицы PSG | Win0 через `wc_mng0_pl()` (`R/src_sdcc/lib/vgm.c:366-368, 1147, 1164`) |
| 4 | код gzip inflate | Win3 прямым `OUT #13AF`, физ. страница = `(#6002)+4`, затем `JP #C000` с SP=#FFF0 (`R/src_sdcc/asm/inflate_call.s:45-110`) |
| 5 | блоки init/тишины чипов | Win3 через `wc_mngc_pl(CMDBLK_PAGE)` (`vgm.c:1135`) |

- Музыкальный файл грузится в страницы видеобуфера WC #20–#5F (1 МБ):
  `wc_mngcvpl(i)` + `wc_load512(0xC000,32)` на страницу
  (`R/src_sdcc/main.c:537-556`).
- Прямая запись в порты страниц в обход распределения WC: TAP-страницы WC
  #A1–#BF — исходный VGZ, страница #EA — буфер распаковки
  (`main.c:577-597`, `asm/inflate.asm:41`); прямой `sfr_page3`
  (`main.c:856-908`).
- **Предупреждение в коде: любой вызов WC API сбрасывает отображение Win3**
  (`main.c:561-563`).

### crt0 (`R/src_sdcc/asm/crt0.s`)

`_plugin_entry` на #8000 (crt0 линкуется первым). Сохраняет то, что передаёт
WC: HL/DE = размер файла, BC = имя, A' = индекс расширения, HL'/DE' = индекс и
число файлов. `gsinit` обнуляет `_DATA` и копирует `_INITIALIZER` в
`_INITIALIZED` (важно: WC повторно входит в плагин при next/prev файле).
Вызывает `main`, возвращает A = `_wc_exit_code`. **IX надо сохранять.**

### Прерывания (`R/src_sdcc/asm/isr.s`, всё на ассемблере)

- WC работает в IM2 с I=#5B. `isr_init` сохраняет вектор кадра из #5BFF,
  ставит свой, INTMASK=1, IM 2 (`isr.s:110-156`).
- На каждом прерывании перепрограммирует VSINTH/VSINTL/HSINT тремя OUTI из
  5-байтной таблицы `pos_table` → 14, 28 или 56 прерываний на кадр
  71 680 тактов (683, 1367, 2734 Гц). **Это механизм «многих прерываний
  за кадр» — годится для музыки и для сплитов экрана.**
- Обработчик исполняет 4-байтные команды из двойных буферов
  `cmd_buf_a`/`cmd_buf_b` (по 512 байт); коды команд — `R/src_sdcc/inc/isr.h`.
- Обработчик WC вызывается из главного цикла через `call_wc_handler`
  (DI; JP на сохранённый вектор) (`isr.s:549-555`).
- Опрос PS/2 в WC отключается `wc_int_pl(WC_INT_NO_PS2)`
  (`main.c:976-977`); клавиатура читается напрямую из FIFO PS/2 в CMOS
  TS-Config: порты #EFF7/#DFF7/#BFF7, регистр #F0 (`R/src_sdcc/lib/keys.c:1-50`).
- **Каждая запись в OPL3/AY/SAA — CPU сбрасывается на 7 МГц (#20AF=1), затем
  обратно на 14 МГц** (`isr.s:309-420`).

### Файловый ввод-вывод через WC

- Плагин получает файл, уже установленный на начало; читает `wc_load512`
  (функция #30: HL = адрес, B = число блоков по 512, A=#0F — конец файла).
- **В WC нет seek.** `R/frontend/plugin/src/main.c:241-284` делает его через
  rewind (`wc_gipagpl`) + skip (`wc_loadnone`, ≤255 секторов за вызов).
  Особенность: сразу после rewind skip не двигает — нужно одно реальное
  чтение.
- Открыть другой файл: `wc_stream(0xFE)` (клон потока), `wc_stream(0xFF)`
  (в корень), `wc_fentry(флаг+имя)`, `wc_gfile()`, затем `wc_load512`
  (`R/src_sdcc/inc/wc_api.h:961-974`).
- Все обёртки — `R/src_sdcc/lib/wc_api/*.s`. `wc_api.h` (1883 строки)
  документирует полную карту страниц TS-Config/WC (`:449-506`, `:780-880`).

### Заголовок WMF (`R/src_sdcc/scripts/ihx2wmf.js`)

Файл: заголовок 512 байт, код (добит до 16К, если есть доп. страницы), доп.
страницы. Поля: +16 `"WildCommanderMDL"`, +32 версия #10, +34 число страниц,
+35 страница на #8000 (0), +36 шесть пар (страница, секторов), ≤32 секторов в
паре; +64 расширения; +161 макс. размер файла FFFFFFFF; +165 имя (32 байта);
+197 = 0. Лимит шести пар → с плагином грузится ≤96 КБ.

### Варианты (`R/src_sdcc/build_variants.ps1`)

Для каждого варианта перегенерируется только `inc/variant_cfg.h`. Три уровня
ISR: 2734 Гц (шаг 1280, 56 записей), 1367 Гц (2560/28), 683 Гц (5120/14),
у каждого несколько бюджетов команд → 8 вариантов, плюс копии `_ns`
(без коротких ожиданий) → 16 сборок. Это A/B-тест таймингов ISR.

### Драйвер OPL3

- API: `R/src_sdcc/inc/opl3.h`, `R/src_sdcc/asm/opl3.s` (в текущей сборке не
  линкуется):
  - `opl3_write_b0` / `opl3_write_b1`: **порты #C4/#C5 (банк 0) и
    #C6/#C7 (банк 1)**;
  - `opl3_init`: банк 1 регистр 5 = 1 (режим OPL3), регистр 1 = #20, далее
    `opl3_reset`;
  - AY/AY2 (#FFFD/#BFFD), SAA/SAA2 (#01FF/#00FF, #01FE/#00FE), `tsconf_out`.
- В рабочей сборке запись в OPL3 идёт через очередь команд ISR.
- Последовательности init/тишины — блоки VGM-опкодов в `R/src_sdcc/asm/cmdblocks.asm`.
- MultiSound управляется записью #F0–#FF в #FFFD (`main.c:660-674`).

### Прочие полезные заголовки

- `R/src_sdcc/inc/tsconf.h`: все регистры TS-Config как `(reg<<8)|#AF`,
  объявления `__sfr __banked`, режимы DMA, векторы прерываний #FF/#FD/#FB,
  биты MemConfig, макросы.
- **Ошибка в комментарии `R/src_sdcc/inc/types.h`:** там сказано, что первый
  16-битный аргумент идёт в DE, а 16-битный результат — в HL. На самом деле
  наоборот (**аргумент в HL, результат в DE**) — см. `R/src_sdcc/asm/wc_api.s:4-15`,
  `R/frontend/trdos/fw_glue.s:5-13`.

## 2. `R/frontend`

Z80-сторона проекта внешней звуковой платы: `common/bus_client.*` — клиент
протокола платы на портах #63 (команда) и #67 (данные, DMA);
`plugin/` — тот же плеер как плагин WC (UMPLAYER.WMF); `trdos/` —
автономный навигатор и плеер; `z80_fw/` — ассемблерная библиотека,
линкуемая с SDCC:

| Файл | Что делает |
|---|---|
| `sd.s` | SD через Z-Controller, порты #57/#77, только чтение, CMD18 (многосекторное чтение), может читать сразу в порт платы |
| `fat.s` | монтирование FAT32 (таблица разделов / BPB), длинные имена → CP866, кэш сектора FAT |
| `file.s` | два слота файлов (рабочий и предвыборка); цепочка кластеров каждого файла хранится как runs в своей странице (до 2730 runs на страницу), побайтный seek, чтение секторами и байтами |
| `dir.s` | загрузка всего каталога в одну страницу |
| `page.s` | переключение страниц — **только 128K**: порт #7FFD с теневой копией, страницы 0–7, отвергает 2 и 5 |
| `irq.s` | IM2, 257-байтная таблица в #B600, заполненная #B7, `JP` в #B7B7 |
| `kbd.s`, `scr.s`, `font.s` | матрица клавиатуры ZX с кольцевым буфером, вывод на экран ZX, шрифт CP866 |

- **FAT/SD без WC:** `sd.s` работает с картой напрямую (логика из драйвера
  TS-BIOS); `fat.s` монтирует том; `file.s` превращает цепочку кластеров в
  runs → seek считается арифметикой, без хождения по FAT.
- C-обвязка: `R/frontend/trdos/fw.h` и `fw_glue.s` (переводит ошибки через
  флаг C в коды возврата, меняет порядок слов 32-бит значений, сохраняет IX).
- Автономный crt0 (`R/frontend/trdos/crt0.s`): `jp init` первым байтом на
  #6000; SP=#BF00, обнуление DATA, копия INITIALIZER; при выходе — IM1 и `rst 0`.

## 3. `R/WC/source` — Wild Commander

### API плагинов (`R/WC/source/plugins/READ_ME.TXT`, система плагинов #10)

**Заголовок и вход:** +34 число выделяемых страниц (незагруженные остаются
как постоянные буферы даже после выхода), +35 страница на #8000, +36 шесть
блоков (страница, секторы), +63 флаг Enter/F3, +64 32 расширения, +161 макс.
размер файла, +165 имя, +197 когда вызывать (#00 по расширению, #01 при
загрузке, #02 скринсейвер, #03 меню F10, #04 Shift-F3, #11–#15 F2/F4),
+198/+204 тексты меню, +260 структура параметров INI.

- Загрузчик WMF принимает версии #02–#10 (`R/WC/source/MD20.ASM:6-7`,
  `R/WC/source/WCVW.ASM:511-537`).
- Страницы плагинов выделяются подряд из #61–#A0 — 64 страницы на все
  загруженные плагины (`MD20.ASM:80-82`); заголовки — в странице #60.
- Вход `CALL #8000`: A = тип вызова, DE:HL = размер файла, BC = имя,
  IX = панель, A' = индекс расширения, DE'/HL' = число/индекс файлов.
- Возврат A: 0 выход, 1 не распознан, 2 следующий файл, 4 предыдущий,
  3 перечитать каталог.

**Системные переменные:** #6000–#6003 — страницы в Win0–Win3, #6004 флаг ESC,
#6005 флаг Enter, #6009 таймер, #600D тип видео-ЦАП, #600E высота экрана.
#6006 — точка входа API (A = номер функции, портит BC'). #6020 — переход по
HL в странице плагина A; #6028 — вызов с сохранением всего, кроме A и HL.

**Функции API:**

| Группа | Функции |
|---|---|
| Память | MNGC_PL 0 (страница плагина в #C000; #FF — страница шрифта, #FE — текстовый экран), MNG0_PL 78 (в #0000; структуры для файловых вызовов тогда должны быть ≥#8000), MNG8_PL 79 |
| Окна и текст | PRWOW 1, RRESB 2, PRSRW 3, PRIAT 4, GADRW 5, CURSOR 6, CURSER 7, YN 8, ISTR 9, NORK 10, TXTPR 11, MEZZ 12, SCRLWOW 84 |
| Система | DMAPL 13 (DMA: RAM→RAM, BLT, FILL, CRAM, SFILE), TURBOPL 14, GEDPL 15 (восстанавливает палитру и текстовый режим WC, портит #1000–#1447), INT_PL 86 (#FF — установить свой обработчик прерываний по HL), PRM_PL 83 |
| Клавиатура | функции 16–47 и 85 |
| Файлы | LOAD512 48, SAVE512 49, GIPAGPL 50, TENTRY 51, CHTOSEP 52, TMRKDFL 54, ADIR 56, STREAM 57, FindNext 58 (портит #0000–#1FFF), FENTRY 59, LOAD256 60, LOADNONE 61, GFILE 62, GDIR 63, MKfile 72, MKdir 73, REName 74, DelFl 75 |
| Графика | MNGV_PL 64 (показать видеобуфер 0–4), MNGCVPL 65 (видеостраницы #00–#3F), MNG0VPL 80, MNG8VPL 81, GVmod 66 (разрешение и режим), GYoff/GXoff 67/68, GVtm/GVtl/GVsgp 69–71 |

**Ограничения:** одно чтение/запись не должно пересекать #FFFF→#0000.
Карта страниц WC — `R/WC/source/comments.txt:40-109`: #4000–#7FFF — WC
(FAT-движок, стек #5BFF, код #6000–#7FFF); вектор прерываний WC — #5BFF
(`MD20.ASM:23`). **SD-драйвер WC использует DMA в обход аппаратного кэша —
закэшированные данные могут устаревать** (`R/frontend/plugin/src/lib/wc_api/wc_cache.s`).

**Плагины с графикой TS-Config** входят одинаково: `MNGV_PL(буфер)` +
`GVmod(режим)`, иногда прямая запись в FMAddr #15AF для палитры; выход —
`GEDPL` и `RET A`. Примеры: `R/WC/source/plugins/plasmatw/` (sjasmplus,
360x288 256 цветов, DMA, кэш, 4 страницы), `bmpview/PLUGBP.ASM:95-187`,
`video_pl/PLUGXX.ASM:72-126` (обработчик INT_PL), `gif_view/GIFVIEW.ASM`.

**Загрузчики внутри WC** (`R/WC/source/WCVW.ASM`): таблица расширений
SPG → `RUNSPG`, `$C` → `RUNHOB`, WMF → `LDPLG` (`WCVLS.ASM:311-314`).
`$C` требует старт ≥#6000 и длину <#A000 (`WCVW.ASM:187-222`). SPG —
`WCVW.ASM:229-354`. Горячее меню `WC.MNU` тоже запускает SPG и `$C`
(`plugins/file_cr/PLUG06.ASM`, `RUNNERS.ASM`).

**Драйверы:** `R/WC/source/DSDZC.ASM` — SD (работает с #3800),
`R/WC/source/CORE32.ASM` — FAT32 чтение/запись (с #4000). Синтаксис ALASM,
концы строк CR.

## 4. `R/tsbios`

- Загрузочное ПЗУ TS-Config. RST 8 — ждать DMA, RST 10 — FAT-движок,
  RST 18 — «BIOS API» (просто `ret`) (`R/tsbios/src/ts-bios.asm:15-31, 1039`).
- Грузит `boot.$c` (обычно WC) с SD или IDE (`ts-bios.asm:255-300`, `booter.asm`).
- `R/tsbios/src/tsfat.asm` (1750 строк, sjasmplus) — порт FAT-движка WC,
  самодостаточный, с драйверами SD (Z-Controller) и IDE (`INIsd` — строка 1390).
  API (`R/tsbios/txt/ts-bios_fat_engine.txt`): READ512/WRITE512 (CDE = адрес,
  B = секторы), SEEK0, SEEK512 (заглушка), SKIP512, FENTRY/SETDIR/MKFILE/MKDIR/
  DELFILE/SETROOT, CRTSTREAM/SELSTREAM/DELSTREAM (последние два — заглушки);
  имена — флаг + 8.3 заглавными; ошибки 0–25.
- Работает только пока подключено ПЗУ BIOS (страница #F7 в Win2, стек #C000).
  **После загрузки программа сервисов BIOS не получает.**
- `R/tsbios/src/pff/` — Petit FatFs 0.03 с драйвером Z-Controller под IAR;
  нужно портировать на SDCC; Petit FatFs не умеет создавать/растить файлы.
- `R/tsbios/src/dehst.asm` — распаковщик Hrust.

## 6. `R/Unreal` — эмулятор и формат SPG

### Эмулятор

- `R/Unreal/cfg/Unreal.ini` уже настроен на TS-Config: `HIMEM=TSL`,
  `RAMSize=4096`, `TS_VDAC=5BIT`, `ZC=1`, `[ZC] SDCARD=wc.img`,
  `[HDD] Image0=wc.img`, `[ROM] TSL=rom\zxevo.rom` (образы TS-BIOS в
  `R/Unreal/cfg/rom/`), `RESET=SYS` (TS-BIOS → WC с образа карты).
- **`MoonSound=1` даёт YMF262 на портах #C4–#C7 — OPL3 работает в
  эмуляторе** (`R/Unreal/hardware/sound/dev_moonsound.cpp:97-108`).
  `Saa1099=0` по умолчанию.
- Форматы (`R/Unreal/snapshot.cpp:65-182`): SNA 48/128, **SPG 0.0/0.1/0.2/1.0**,
  z80, sp, tap, tzx, csw, образы дисков, Hobeta. WMF не грузит (плагины —
  только внутри эмулируемого WC).
- SPG до 4 МБ (`R/Unreal/vars.h:10`); опция `SPGMemInit`; автозагрузка
  `[AUTOLOAD] snapshot=`.
- Запись в неизвестный порт #xxAF логируется как `Illegal port!`
  (`R/Unreal/hardware/io.cpp:1652`) — `src_sdcc` использует #FFAF/#FEAF/#FDAF
  как отладочные порты трассировки.
- Эмуляция TS-Config — `R/Unreal/hardware/clones/tsconf.cpp`; собирается в
  VS2022 (`R/Unreal/VS_CODE_SETUP.md`).

### Формат SPG 1.0

Письменной спецификации в REF нет; восстановлено по `R/Unreal/snapshot.h:6-34`
и загрузчику WC `R/WC/source/WCVW.ASM:229-354`:

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 32 | автор |
| 32 | 12 | `"SpectrumProg"` |
| 44 | 1 | версия = #10 |
| 45–47 | 3 | день, месяц, год |
| 48 | 2 | стартовый PC |
| 50 | 2 | SP |
| 52 | 1 | страница в Win3 |
| 53 | 1 | биты 1:0 — частота CPU (0 = 3.5, 1 = 7, 2 = 14 МГц), бит 2 — прерывания разрешены при старте |
| 54 | 2 | pgmgr_addr (только 0.x) |
| 56 | 2 | rsd_addr: сюда WC копирует 16 байт кода передачи управления |
| 58 | 2 | число блоков |
| 60–62 | 3 | время |
| 63 | 17 | резерв |
| 80 | 32 | создатель |
| 112 | 144 | резерв |
| 256 | 3x256 | дескрипторы блоков |
| 1024 | … | данные блоков подряд |

Дескриптор блока (3 байта):
- байт 0: биты 4:0 — смещение в странице в единицах 512 байт; бит 7 —
  последний блок;
- байт 1: биты 4:0 — секторов − 1 (до 16 КБ); биты 7:6 — упаковка
  (0 нет, 1 MegaLZ, 2 Hrust), размер — упакованный;
- байт 2: физическая страница (0–255).

WC останавливается по биту 7, Unreal считает блоки — **ставить оба**.

### Что делает загрузчик WC

1. Читает заголовок 1 КБ и таблицу дескрипторов.
2. Для каждого блока подключает целевую страницу в #C000 и читает блок в неё.
   Упакованные — в буферную страницу #F4 и распаковываются. Блоки для
   страниц 2 и 5 перенаправляются в #F6/#F5 и копируются в конце.
3. Настраивает машину: видеостраница 5, режим ZX, IM1 с I=63; страница 5 в
   Win1, 2 в Win2, страница из заголовка в Win3; частота CPU из байта 53;
   DMA остановлен; HL'=#2758, IY=#5C3A.
4. Переходит на rsd_addr: этот код ставит MemConfig #21AF=1, BASIC48 ROM (3)
   в Win0, DI/EI, прыжок на PC.
5. После этого WC больше нет — сервисов нет.

Осторожно: 16 байт по rsd_addr затираются; загрузчик использует #F4–#F6 и
страницу, стоящую в Win0 во время загрузки. **Держать блоки вне #F0–#FF** —
вывод, не документировано.

## 7. Что берём в проект

1. **Упаковка:** написать `mkspg.js` на основе `R/src_sdcc/scripts/ihx2wmf.js`
   и `SS/scripts/tools/cutbin.js`, по заголовку из `R/Unreal/snapshot.h`.
   На входе — `.ihx`/`.bin` на каждую 16К-страницу + страницы данных, на
   выходе — SPG 1.0. Сначала без упаковки; MegaLZ/Hrust потом (их
   распаковывают и WC, и Unreal). Тестировать загрузкой SPG прямо в Unreal с
   `wc.img`, где лежат файлы данных (`SS/scripts/build_sd.bat` + `robimg.exe`).
2. **Предлагаемая карта памяти:**

| Окно | Назначение |
|---|---|
| Win0 | RAM-страница «ядра» (ROM→RAM через MemConfig #21AF: W0_RAM, W0_MAP_DIS, W0_WE — `R/src_sdcc/inc/tsconf.h:253-261`, + PAGE0 #10AF): таблица IM2 и ISR, помощники банкинга, драйвер SD/FAT, буферы секторов, стек |
| Win1 | общий C-код и глобальные переменные |
| Win2 | банкованный код: SDCC `__banked` с `set_bank`/`get_bank`, пишущими #12AF, один `--codeseg` на банк |
| Win3 | страницы данных и ресурсов через #13AF |
| где угодно в 4 МБ | видео-, тайловые и спрайтовые страницы, заполняются DMA |

3. **Диск:** портировать `R/frontend/z80_fw/{sd,fat,file,dir}.s` +
   `R/frontend/trdos/fw_glue.s`/`fw.h`; переписать `page.s` под порт #13AF и
   256 страниц, добавить слотов файлов. Для сохранений (нужна запись) —
   портировать `R/tsbios/src/tsfat.asm` (чтение/запись) или
   `R/WC/source/CORE32.ASM` + `DSDZC.ASM`, либо Petit FatFs с заранее
