# Конвертер данных `oxzconv` (утилита для ПК)

## 1. Назначение и сценарий пользователя

Дистрибутив проекта = две части:
1. **Игра для TS-Config** (SPG) — движок, одинаковый для обеих игр.
2. **Утилита для ПК** `oxzconv`: пользователь указывает каталог **своей**
   копии UFO: Enemy Unknown / X-COM: UFO Defense **или** X-COM: Terror from
   the Deep, утилита выдаёт каталог данных, который он копирует на SD-карту.

Решения пользователя (2026-09-14):
- **Приоритет — Terror from the Deep**, но движок и конвертер
  **универсальные**: как OpenXcom, умеют обе части.
- **Различия игр выравнивает конвертер**: на выходе единый формат, движок
  про версию знает минимум (что есть в данных).
- Всё адаптируется под железо заранее, на ПК.

Данные оригинала не распространяются: конвертер работает только с копией
пользователя. В утилиту входят файлы OpenXcom (правила `*.rul`, строки,
шрифты — GPL, `REF/OpenXcom/bin`), это не данные оригинала.

## 2. Утилита `OxzConv.exe` (C#, .NET Framework 4.8)

Решение пользователя: **один консольный exe на .NET Framework 4.8** (есть на
любой Windows 10/11, ставится на 7/8.1), без установки чего-либо. Парсер YAML
(YamlDotNet) и нужные файлы OpenXcom (правила, строки en-US, шрифты) вшиты в
exe ресурсами (~1.3 МБ).

```
OxzConv.exe                                  # спросит каталог игры и куда писать
OxzConv.exe <каталог игры>                   # можно перетащить папку на exe; данные — рядом с exe
OxzConv.exe --game DIR --out DIR [--preview DIR] [--oxcom <bin OpenXcom>] [--lang en-US]
OxzConv.exe headers <каталог>                # заголовки C для движка (зовёт tools/build.ps1)
```

Результат — каталог `OXZ/<игра>/`, его копируют в корень SD-карты.

Сборка (все кэши dotnet/NuGet — в `tmp/dotnet`, правило проекта):
`powershell -File tools\dotnet.ps1 build OxzConv\OxzConv.csproj -c Release`
→ `tmp/oxzconv/bin/Release/OxzConv.exe`. Для разработки:
`--out tmp/sd --preview tmp/preview`.

Код `OxzConv/`: `Program.cs` (загрузка вшитой YamlDotNet),
`Cli.cs`, `Core/Converter.cs` (шаги), `Core/GameFs.cs` (каталог игры без
учёта регистра, UFO/TFTD), `Core/Formats.cs` (SCR, SPK, BDY, PCK/TAB 16/32,
DAT, LBM, палитры), `Core/Png.cs` (zlib вручную — в 4.8 нет ZLibStream),
`Core/Cram.cs`, `Core/Sprites.cs`, `Core/Pack.cs`, `Core/ResIds.cs`
(+ реестры), `Core/Strings.cs`, `Core/Fonts.cs`, `Core/Interfaces.cs`,
`Core/Music.cs`, `Core/Headers.cs`, `Core/OxcomData.cs`, `Core/Yaml.cs`;
реестры — `Data/*.txt`, `Data/screen_backgrounds.json`.

Первая версия была на Node.js; перенос на C# проверен **побайтным
совпадением всех 18 выходных файлов обеих игр** и совпадением заголовков,
после чего версия на Node удалена.

- `--game` — каталог с `GEODATA`, `GEOGRAPH`, `UFOGRAPH`, … (Steam:
  `.../XCOM` или `.../TFD`). Регистр имён не важен.
- Игра определяется автоматически: TFTD — есть `TERRAIN/LOFTEMPS.DAT`,
  `UFOGRAPH/*.BDY`, `FLOP_INT`; иначе UFO.
- `--out` — корень карты: пишется `OXZ/UFO/…` или `OXZ/TFTD/…`.
- `--preview` — PNG всех картинок для проверки глазами (в `tmp/`).

## 3. Выравнивание UFO / TFTD (как в OpenXcom `Mod::loadVanillaResources`)

| Что | UFO | TFTD | Логическое имя в наших данных |
|---|---|---|---|
| Палитры | `PALETTES.DAT` 5 шт. по 774 байта | 3 шт. | `PAL_GEOSCAPE`, `PAL_BASESCAPE`, `PAL_GRAPHS`, `PAL_UFOPAEDIA`, `PAL_BATTLEPEDIA` (у TFTD — какие есть) |
| Палитры боя | палитра 4 + серая рампа 240–255 | `UFOGRAPH/D0..D3.LBM` (глубины) | `PAL_BATTLESCAPE[_1.._3]` |
| Уфопедия | `GEOGRAPH/UP*.SPK` | `GEOGRAPH/UP*.BDY` | `UP001`… (одно пространство имён) |
| Куклы инвентаря | `UFOGRAPH/MAN_*.SPK` | `UFOGRAPH/MAN_*.BDY` | `MAN_*.SPK` |
| Панели боя | `UFOGRAPH/*.PCK` (SPK внутри) | `UFOGRAPH/*.BDY` | `ICONS.PCK`, `DETBORD.PCK`, `TAC01.SCR`… |
| TAB спрайтов | 2-байтные смещения | 4-байтные | число кадров, формат единый. Размер записи — по первым 4 байтам: 0 как int32 — 4-байтные (`Formats.TabFrames`; до 2026-09-15 проверялось иначе, и BASEBITS TFTD давал 27 кадров вместо 54 — не рисовались корабли в ангарах и мини-вид баз) |
| LOFTEMPS | `GEODATA` | `TERRAIN` | `LOFTEMPS` |
| Интро | `UFOINTRO/UFOINT.FLI` | слайды `FLOP_INT/*.LBM` + подписи (`cutscenes.rul`) | слайд-шоу (FLI — позже или никогда) |
| Музыка | `SOUND/ADLIB.CAT` | `SOUND/ADLIB.CAT` (позиции — `music.rul`) | треки OPL |
| Правила, строки | OpenXcom `xcom1` | OpenXcom `xcom2` | бинарные таблицы, одна структура |

## 4. Адаптация под железо (02, 08)

- **Картинки — 8 бит на пиксель, без сжатия**, строки подряд: DMA копирует
  прямоугольник одной командой (источник линейный, приёмник с шагом 512 —
  `D_ALGN`). Полноэкранный фон 320x200 = 64 000 байт = 4 страницы.
- **Ширина — чётная** (DMA работает словами), спрайты **обрезаются** по
  непрозрачным пикселям (смещение сохраняется), 0 — прозрачный (BLT1).
- **Палитры — 256 слов CRAM** (`0RRRRRGG GGGBBBBB`, 5 бит, `round(v6·31/63)`).
  Движок при загрузке: на VDAC (целевая конфигурация) ставит бит 15 —
  линейный RGB555; на стоковом ZX-Evo (ШИМ-ЦАП, различимы 0–24) пересчитывает
  каналы в 0..24 (02 §4).
- **Выравнивание на сектор 512 байт**: каждый ресурс в пакете начинается с
  границы сектора → загрузка «секторы с SD → DMA SPI→RAM» прямо в страницу,
  без копирования.
- Имена файлов **8.3 заглавными** (FAT без длинных имён проще).
- Строки — однобайтовая кодировка (латиница + CP866 при переводе),
  правила — таблицы с числовыми ссылками вместо строковых ключей.

## 5. Формат пакета `*.PAK`

Сектор = 512 байт, числа little-endian.

Заголовок (секторы `0 .. hdr_sectors-1`):

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 4 | `OXZP` |
| 4 | 1 | версия = 1 |
| 5 | 1 | игра: 1 — UFO, 2 — TFTD |
| 6 | 2 | число записей N |
| 8 | 2 | секторов заголовка |
| 10 | 6 | резерв |
| 16 | 16·N | записи |

Запись (16 байт):

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 2 | id ресурса |
| 2 | 1 | тип |
| 3 | 1 | флаги |
| 4 | 2 | смещение в секторах от начала файла |
| 6 | 4 | размер в байтах |
| 10 | 2 | параметр A (ширина / число кадров / …) |
| 12 | 2 | параметр B (высота / …) |
| 14 | 2 | параметр C |

Типы: 1 `IMG8` (w, h; байты строками), 2 `SPRSET` (набор обрезанных
кадров), 3 `PAL` (256 слов CRAM), 4 `FONT`, 5 `STR`, 6 `TABLE`, 7 `MUSIC`,
8 `BLOB`.

`SPRSET`: `u16 n, u8 cell_w, u8 cell_h`, затем n записей по 6 байт
(`u8 x, u8 y, u8 w, u8 h, u16 offset`, w чётная, w=0 — пустой кадр;
offset — от начала данных кадров, в словах, т.е. ×2) и данные кадров подряд.

Идентификаторы ресурсов — таблица логических имён `tools/conv/lib/resids.js`
(общая для обеих игр, фиксированные номера); из неё генерируется
`src/inc/res_ids.h` для движка. Ресурсов, которых нет в данной игре, в
пакете просто нет.

| Файл | Содержимое | Где |
|---|---|---|
| `PAL.PAK`, `LANG.PAK`, `RULES.PAK`, `GEO.PAK` | палитры; строки и шрифты; правила; `GEOBORD`, `GRAPH(S)`, `INTERWIN`, `BASEBITS`, `INTICON`, `SCANG` | вшиты в SPG (#50–#AF) |
| `BACK.PAK` | фоны окон `BACKnn.SCR` (с 2026-09-15; раньше — в `GEO.PAK`) | SD-карта |
| `UFOP.PAK` | картинки Уфопедии, `UP_BORD*` | SD-карта |
| `ITEMS.PAK` | предметы (`BIGOBS`…), куклы брони | SD-карта |
| `CUTS.PAK` | слайды заставок (`cutscenes.rul`, IMG8 320×200, id `CUT:<путь>`; палитры и таблица `CUTSCENES` — в RULES.PAK), с 2026-09-15 | SD-карта |
| `BATUI.PAK` | интерфейс боя (`TAC00/01`, `ICONS`, курсоры, дым, панели) | SD-карта |
| `BATTLE.PAK` | карты боя: `BATMAP0..2` (готовые поля) и их тайлсеты `BATTILE0..2` (с 2026-09-18) | SD-карта |
| `MUSIC.PAK` | музыка | пока не используется движком |

**`BATTLE.PAK` (`Core/Battle.cs`)** — временное решение до генератора карт
(16 §3): конвертер сам замащивает поле 4×4 блоками 10×10 первых доступных
террейнов (TFTD — SEABED, CORAL, VOLC; UFO — CULTA, DESERT, FOREST) и
складывает результат в готовый ресурс, движок только рисует. Ресурс
`BATMAP<i>` (`BLOB`, A = sx, B = sy, C = sz):

| Смещение | Поле |
|---|---|
| 0..2 | `sx, sy, sz` (клеток) |
| 3 | число тайлов (≤ 255) |
| 4..5 | номер ресурса тайлсета (`SPRSET`) |
| 6..7 | резерв |
| 8.. | по 4 байта на тайл: `yofs` (MCD `P_Level`), флаги (1 `noFloor`, 2 `stopLOS`, 4 `ufoDoor`, 8 `door`, 16 `gravLift`), `bigWall`, `tileType` |
| … | клетки по 4 байта: номера тайлов + 1 (пол, западная стена, северная стена, объект), 0 — пусто |

Порядок клеток: X быстрее всего, затем Y, затем **Z снизу вверх** (в
оригинале Z идёт сверху вниз — переворачивает конвертер). Номер тайла — он
же номер кадра в тайлсете карты: в тайлсет попадают только использованные
записи MCD (TFTD: 65–78 тайлов на карту, тайлсет 38–49 КБ, карта 12–25 КБ).
Эталон вида (алгоритм художника, камера в центре) пишется в
`tmp/preview/<игра>/BATMAP<i>_<террейн>.png` — с ним сверяется картинка
движка.

Пакеты с SD читает `src/kernel/sdres.c` (13_sd_card.md).

## 7. Форматы ресурсов (дополнение к §5)

**FONT** (шрифты OpenXcom `bin/common/Language/Font.dat` + PNG):
`u8 cell_w, u8 cell_h, i8 spacing, u8 first=#20, u16 n`; `n x {u8 width,
u16 offset}`; глифы — `cell_h` строк по `ceil(width/2)` байт, **4 бита на
пиксель = уровень 0..5** (0 — прозрачный). Цвет пикселя при выводе =
`цвет_текста + уровень * mul` (mul = 1, 3 — «контраст»), как `PaletteShift`
в OpenXcom. Глиф для кода `c`: `c - #20` (#20..#7E) или `c - #80 + 95`.
Ширина глифа — по непрозрачным столбцам ячейки (как `Font::init`); пробел —
половина ячейки.

**STR** (строки `common` + `xcom1|xcom2`, язык `--lang`, по умолчанию en-US):
`u16 n`, `n` 3-байтных смещений от конца таблицы (`#FFFFFF` — строки нет),
строки с нулём. **Строка не пересекает границу 16 КБ** — движок читает её
целиком через Win3. Кодировка байта: `#01` {ALT}, `#02` {SMALLLINE}, `#03`
{N}, `#04` неразрывный пробел, `#0A` {NEWLINE}, `#10..#19` {0}..{9}, ASCII
как есть, прочие символы — `#80..#FF` по кодовой таблице `CHARSET`
(u16 кодовые точки). Номера: сначала ключи движка
(`Data/engine_strings.txt`), затем прочие ключи игры по
алфавиту (на них ссылаются правила). **Мн. число** — ключи `STR_X_one` и
`STR_X_other` подряд (раньше `#one`: такой ключ движок не находил, и
`STR_HOUR` показывался как «#383», а `STR_DAY` — только «Day»); в
`engine_strings.txt` — парами (`STR_DAY_one/other`, `STR_HOUR_one/other`,
`STR_NO_MORE_EQUIPMENT_ALLOWED_one/other`). Движок: `str_plural(out,
STR_X_one, n)` — `one` при n = 1, иначе следующий номер (правило en-US).

**UI** (`interfaces.rul`): см. `tools/conv/lib/interfaces.js` — по экрану
палитра, родитель, элементы (id, флаги «что задано», color, color2, border,
pos, size, TFTDMode); элементы родителя развёрнуты при конвертации.

**Реестры с фиксированными номерами** (общие для UFO и TFTD, только
дописывать): `Data/engine_strings.txt` (961), `Data/ui_screens.txt` (98),
`Data/ui_elements.txt` (163), `Data/music_types.txt` (47), статические
ресурсы — `Core/ResIds.cs`. `OxzConv.exe headers` делает из них `res_ids.h`,
`str_ids.h`, `ui_ids.h`, `mus_ids.h` (вызывается из `tools/build.ps1`,
выход в `tmp/build/gen`). Реестры собраны однократно (из `interfaces.rul` и
`music.rul` обеих игр, ключи строк — из `REF/OpenXcom/src`).

**MUSIC** (`ADLIB.CAT`, у UFO интро — `AINTRO.CAT` за концом): плеер
оригинала (OpenXcom `adlplayer.cpp`, Volutar) портирован в
`tools/conv/lib/music.js` и выполняется **офлайн** с родным тиком
44100/629 = 70.11 Гц; записи в регистры раскладываются **по кадрам
TS-Config 3 500 000 / 71 680 = 48.83 Гц** (идея пользователя: раз в кадр
отдавать данные в OPL3). Движку на Z80 остаётся в кадровом прерывании
вывести пары «регистр, значение» — без разбора нот.
- 12 голосов плеера: 0–8 → банк 0, 9–11 → банк 1, каналы 0–2 (операторы
  смещений 24–29 → 0–5 банка 1); режим OPL3 (NEW=1), в C0–C8 биты L+R.
- Повторяющиеся значения регистров отбрасываются.
- Формат потока — в заголовке `lib/music.js`; номер ресурса = `#0300` +
  номер типа в `data/music_types.txt` (47 типов обеих игр).
- Нагрузка: худший кадр ~97 записей (≈6 тыс. тактов, ~2% кадра), в среднем
  1–2 записи; TFTD 22 трека, 28.5 мин, 187 КБ; UFO 14 треков, 400 КБ.
- Для прослушивания на ПК конвертер пишет VGM (YMF262) в
  `--preview/<игра>/music/*.vgm` (слушать любым VGM-плеером, в т.ч. плеером
  пользователя для TS-Config). **Проверить на слух.** Некоторые треки UFO
  идут до повтора 8–9 минут — сверить с оригиналом.
- «Хорус» OpenXcom (второй расстроенный чип) не воспроизводится — это
  добавка эмулятора OpenXcom; при желании можно добавить на свободных
  каналах 3–8 банка 1.

**Палитра экрана** (исправлено в предпросмотре, так же должен делать
движок): палитра из `interfaces.rul` (по умолчанию `PAL_GEOSCAPE`) + блок
`BACKPALS` (16 цветов) в цвета 224–239; номер блока — `color` элемента
`palette` (у родителя, если у экрана нет) — `State::setInterface/setPalette`.
Фоны `BACK*.SCR` рисуются только цветами 224–239 — поэтому без подмены блока
«местами цвета не те». Какой экран какой фон рисует —
`tools/conv/data/screen_backgrounds.json` (85 экранов, собрано из кода OpenXcom).

**Таблицы правил** (`RULES.PAK`, `Core/Rules.cs` + `Core/RulesSchema.cs`):
схема описывает поля каждой таблицы (тип, умолчание из OpenXcom — 10),
порядок записей как `sortLists` OpenXcom (craftWeapons — по listOrder
launcher, armors — по storeItem, ufopaedia — раздел + listOrder, units — по
ключу). Запись фиксированного размера, списки — в «хвосте» таблицы; ссылки
между таблицами — номера записей (`#FFFF` — нет, `| #8000` — вторая таблица
в «items|crafts»); строки — номера в `STRINGS`; картинки — номера ресурсов.
Номер ресурса таблицы — `#0040 + номер в схеме`, `#003F` — глобальные
значения и стартовая база. Из той же схемы генерируется `rules.h`
(структуры `r_<таблица>_t`, флаги `<ТАБЛИЦА>_F_*`). Каждая таблица ≤ 16 КБ.

Таблицы (TFTD / UFO): items 150/145 x 91 Б, research 133/137 x 23,
manufacture 42/35 x 21, facilities 17 x 43, crafts 5 x 46, craftWeapons 6 x 24,
armors 24/28 x 36, soldiers 1 x 54, units 34/37 x 33, alienRaces 12/6 x 5,
countries 16 x 13, regions 17/15 x 11, ufos 8 x 28, ufopaedia 133/127 x 24.
Предупреждения о неразрешённых ссылках — в `RULEWARN.TXT` (сейчас только
трупы, которых нет и в OpenXcom).

Статьи Уфопедии (`ufopaedia`): `rule` — номер записи в таблице по типу
статьи (корабль, оружие корабля, юнит, предмет, броня, постройка, НЛО — ключ
статьи = ключ правила); `image` — `image_id`, а у брони UFO (тип 5, в правилах
картинки нет) — кукла `spriteInv` + `M0.SPK` / `.SPK`, как
`ArticleStateArmor` (`ArmorImage`, поиск ресурса через `ResIds.Find`);
`textWidth` у TFTD по умолчанию 157.

Проверка: `OxzConv.exe dump <OXZ\игра> [таблица [число]]` — ресурсы пакетов
или записи с именами полей, текстом строк и названиями записей по ссылкам.

Координаты глобуса (2026-09-14) — двоичные углы: поле `lon` — u16
(65536 = 360°, 360° → #FFFF), `lat` — i16 (16384 = 90°, плюс — юг), `areas`
(зоны стран и регионов) — список `{u16 lonMin, lonMax; i16 latMin, latMax}`
в хвосте. Раньше было `x100` в i16 — долготы больше 327.67° обрезались
(нашлось через `dump`).

**Глобальные значения и стартовая база** (`#003F`, `RulesSchema.Vars`):
`u8 sec, min, hour, weekday, day, month; u16 year; u32 initialFunding (тыс.),
costEngineer, costScientist; u16 timePersonnel; u16 alienFuel, alienFuelAmount;
u8 difficultyCoefficient[5]`; база: `u16 scientists, engineers,
randomSoldiers; u8 n, {u16 facility, u8 x, y}·n; u8 n, {u16 craft, u16 id,
fuel, damage; u8 n, {u16 craftWeapon, u16 ammo}·n; u8 n, {u16 item, u16
qty}·n; u8 n, {u16 item, i16 ammo}·n}·n` (оружие, трюм и техника кораблей);
`u16 n, {u16 item, u16 count}·n`. TFTD — 230 байт.

**Имена солдат** (`NAMES` #0022 в `LANG.PAK`, `Core/Names.cs`): пулы
`common/SoldierName/*.nam` OpenXcom (как `SoldierNamePool`): `u8 n; u16
offs[n]`; пул — `u8 cnt[4]` (maleFirst, femaleFirst, maleLast, femaleLast),

**WORLDMAP** (`#0144`, GEO.PAK; `Core/WorldMap.cs`) — маска полигонов WORLD.DAT для

текстура), `rowStart[180]` — граничных до строки. TFTD 7484 граничных клеток, 98 КБ;
UFO 6770, 91 КБ. Движок — `world_texture` (`src/geoscape/earth/geo.c`).

**GLOBE** (`#0145`, GEO.PAK; `Core/Globe.cs`, v4 2026-09-15) — плоская карта глобуса для
рендера М4в (globe.md §5.4, src/geoscape/earth/globe.c, globe_s.s). Многоугольники WORLD.DAT
перекрываются (OpenXcom рисует их по порядку, поздний сверху) и стыкуются с T-стыками;
конвертер решает это заранее: (1) исходные вершины ближе 3·10⁻⁴ рад к чужому ребру (дуге
большого круга) вставляются в ребро и его многоугольники; (2) все рёбра пересекаются друг с
другом (точки пересечения — новые вершины); (3) у каждого куска текстура слева и справа —
в точках рядом с серединой по правилу OpenXcom (последний по порядку файла многоугольник,
содержащий точку; чёт-нечет в гномонической проекции; нет — океан #FF); (4) куски с одной
текстурой с двух сторон выбрасываются, цепочки на одной дуге с теми же сторонами
склеиваются (до 12°). Остаются только границы, где текстура меняется. Рёбра разложены по
72 ячейкам 30° x 30° по середине, у ячейки — свои копии вершин.
Формат v4: `u16 nCell (72), nVert, nEdge`; ячейка (16 байт): `u16 v0, vn, e0, en`, центр
(6 байт, как вершина), `i16 sinRho` (Q14, радиус шапки + 0.5°; 16384 — не отсекать);
вершина (6 байт): X, Y, Z по 2 байта — `v & 127`, `v >> 7` (индексы T_lo / T_hi таблиц
движка), X = cosφ cosλ, Y = cosφ sinλ, Z = sinφ (Q14, |·| <= 16383, широта минус — север);
ребро (6 байт): `u16 va, vb` — номер вершины в ячейке × 6 (запись проекции движка: x, y, z),
`u8 texL, texR` — текстура слева / справа от va → vb на экране (проекция сохраняет
ориентацию: сторона A × B — справа), #FF — океан; затем сетка 5° `u8 [36][72]` (от λ = 0,
φ = −90°): текстура клетки, если в неё не заходит ни одно ребро, иначе #FE — движку, когда в
окне нет ни одного ребра. TFTD: 733 многоугольника, 76 почти-T-стыков, 897 пересечений →
1298 рёбер, 1399 вершин, 19 КБ; UFO: 2 / 4 → 1197 / 1212, 18 КБ; до 144 вершин и рёбер в
ячейке, радиус ячейки до 33°. Проверка — модель `tools/globe_model.js` против эталона «художник
по многоугольникам». **TEXTURE.DAT** (`#0142`, GEO.PAK) — 39 кадров 32x32 как есть (a = 39).

**CUTSCENES** (`#0031`, RULES.PAK; `Converter.Cutscenes`, 2026-09-15) — заставки
`cutscenes.rul`, только слайд-шоу (видео FLI/VID не переносятся). Таблица: 4 × `u16`
смещение записи (0 — нет) в порядке `intro, winGame, loseGame, tleth` (= `CUT_*`,

u16 палитра, u16 строка подписи (FFFF — нет), i16 x, y, w, h (рамка подписи), u8 цвет,

Картинки — LBM 320×200 → IMG8 в `CUTS.PAK` (SD), id `CUT:<путь>`; палитра LBM — ресурс
`CUT:<путь>:PAL` (CRAM, 256 цветов) в RULES.PAK. TFTD: интро `FLOP_INT/INT*` + T'leth,
победа, поражение — 44 картинки, 2.8 МБ; UFO: победа и поражение `UFOINTRO/PICT*` —
7 картинок, 0.44 МБ (интро UFO — только видео). Движок — `src/geoscape/scr_end.c`.

Ещё не в таблицах: развёртывания для боя, terrains, mapScripts, invs,
extraSprites, constants.
