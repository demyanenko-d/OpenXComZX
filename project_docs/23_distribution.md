# 23. Дистрибутив: карта для реального железа

Сборка «всё, что нужно для игры на настоящем ZX Evolution» одной командой:

```
powershell -File tools\dist.ps1            # собрать обе игры и карту
powershell -File tools\dist.ps1 -NoBuild   # только разложить и собрать образ
```

- `distr\` в корне проекта — **содержимое карты** (что копируется в её корень);
- `oxz_card.img` в корне проекта — **образ этой же карты**: и для эмулятора
  (`run.ps1` → `ZC.SDCARD`), и для записи на карту целиком.

Это единственные артефакты вне `tmp\` (просьба пользователя: дистрибутив под
рукой). В git не попадают — `.gitignore`, данные игр распространению не
подлежат. Скрипт — `tools/dist.ps1`, текст инструкции для пользователя —
`tools/dist_readme.txt` (на карте — `README.TXT`, UTF-8).

## 1. Что делает скрипт

1. Собирает обе игры: `build.ps1 -Game UFO -NoCard`, затем `-Game TFTD -NoCard`
   (TFTD последней, чтобы рабочее дерево осталось на игре по умолчанию; `-NoCard`
   — чтобы образ собирался один раз в конце, а не на каждую игру). Код возврата
   `build.ps1` проверяется: при ошибке компиляции скрипт падает (иначе ловушка —
   старый `oxz.spg` от прошлой сборки, см. `findings_log`).
2. Раскладывает `distr\` — это ровно содержимое корня карты:

   | На карте | Откуда | Размер |
   |---|---|---|
   | `OXZTFTD.SPG` | сборка TFTD | 1 092 КБ |
   | `OXZUFO.SPG` | сборка UFO | 958 КБ |
   | `OXZ/TFTD/*.PAK` | `tmp/sd/OXZ/TFTD` (конвертер) | 32 МБ |
   | `OXZ/UFO/*.PAK` | `tmp/sd/OXZ/UFO` | 22 МБ |
   | `boot.$C`, `WC/`, `Help.txt` | `unreal/soft/WC/exe` | 470 КБ |
   | `README.TXT` | `tools/dist_readme.txt` | 4 КБ |

   Из состава Wild Commander взяты только загрузчик, папка `WC` и справка:
   `demo/` (44 МБ чужих демок) и `soft/` (текстовый процессор в `.SCL`) карте
   не нужны. Пакетов на игру — 13, список в скрипте (`$packs`) повторяет
   `pack_name` в `sdres.c` плюс музыку (`music.c`) и глобус (`globe_view.s`);
   новый пакет в конвертере — добавить и сюда, иначе он не попадёт на карту.
   Папка `OXZ\<игра>` перед копированием чистится: устаревших пакетов на карте
   быть не должно.
3. Делает из `distr\` образ `oxz_card.img` утилитой
   `unreal/tools/robimg/robimg.exe`. Образ — вне `distr\`: иначе robimg
   копирует его внутрь самого себя.

`build.ps1` свой образ больше не собирает: если карты нет или данные конвертера
новее образа, он зовёт `dist.ps1 -NoBuild` (игры не пересобираются, SPG берутся
те, что уже лежат в `distr\`). Так тесты всегда идут с той же карты, что уедет
на железо.

## 2. Карта обязана быть FAT32

TS-BIOS грузится **только с FAT32**: на FAT16 он пишет

```
System Meditation:
FAT32 NOT FOUND!
Press SS + Reset to change start-up options
```

(проверено пользователем на образе 128 МБ / FAT16 — первый вариант этого
скрипта). Сам порт читает и FAT16, и FAT32 (`fat.c`), но до порта дело не
доходит — загрузчик читает TS-BIOS.

`robimg` тип FAT не спрашивает, а выбирает по числу кластеров (FAT16, пока их
≤ 65525), поэтому FAT32 получается только на достаточном объёме:

| `-s` (КБ) | `-o` (кластер) | Итог |
|---|---|---|
| 131072 (128 МБ) | 4096 | FAT16 |
| 131072 | 1024 | FAT32 |
| 262144 (256 МБ) | 2048 | **FAT32 — берём это** |
| 262144 | 4096 | `Format ... Error e`, код возврата 0, в образе один MBR без BPB |
| 524288 (512 МБ) | 4096 | FAT32 |

Команды:

```
robimg.exe -p=<образ> -s=262144 -o=2048 -f=0     # создать и отформатировать
robimg.exe -p=<образ> -a=1 -C=<папка>            # залить содержимое папки
```

- `-s` — размер в КБ, `-o` — размер кластера в байтах, `-f` — тип разметки
  (`0` — раздел в MBR, `1` — том с сектора 0 без MBR; **по умолчанию 1**),
  `-a=1` — не форматировать уже готовый образ.
- Берём `-f=0`: карта, отформатированная из Windows, тоже с разделом в MBR, и
  образ для эмулятора должен повторять её. `fat.c` читает оба варианта
  (сектор 0: `EB`/`E9` — сразу BPB, иначе первый FAT-раздел MBR).
- Длинных имён robimg не умеет — в образе они усечены до 8.3
  (`WC/MENU/HRUSTV~1.SPG`). На игру это не влияет (все наши имена 8.3),
  но родное меню WC (`wc.mnu` ссылается на длинные имена) в образе не работает;
  на настоящей карте, скопированной из Windows, имена сохранятся.

Содержимое готового образа можно посмотреть без эмулятора:

```
node tools\fatls.js oxz_card.img
```

## 3. Проверка

- `tools/runtests.ps1` на этом образе — 21 сценарий зелёный (FAT32 + MBR: в
  `fat.c` это другая ветка разбора тома и другая `fat_next`/`chain_skip`, чем
  на прежнем FAT16 без MBR).
- На подменённой сборке UFO — `ufopaedia_ufo`, `globe`, `bat_render`: обе игры
  находят свои пакеты (`sd: OXZ/UFO/BACK.PAK 17` …), бой генерирует карту.
- `tests/boot_card.oxs` (`run.ps1 -Boot -Script tests\boot_card.oxs -Headless`) —
  старт без снапшота, как на железе: снимки в `tmp/shots/boot/`.
  **Ограничение эмулятора**: TS-BIOS в Unreal всегда уходит в Setup (CMOS нигде
  не сохраняется), а выход из Setup — F12, которого машине не передать: Unreal
  забирает F12 себе под сброс, PS/2-буфер (`input.buffer`, включается гостевой
  записью 2 в CMOS ≥ `#F0`) в Setup выключен, а в матрицу ZX F-клавиши не
  входят. Команда сценария `pckey <имя|hex>` шлёт скан-код PS/2 в буфер и
  печатает его состояние — для кода, который буфер включает. Поэтому цепочка
  «TS-BIOS → boot.$C → Wild Commander → ENTER на SPG» проверяется только на
  живой машине или в эмуляторе руками.

## 4. Как этим пользоваться на железе

Кратко (подробно и по-человечески — в `README.TXT` на карте):

1. Карта SD/microSD от 128 МБ, один раздел **FAT32**, содержимое `distr\` —
   в корень карты.
2. Пути к данным зашиты как `OXZ/<игра>/<пакет>.PAK` **от корня карты**:
   папку `OXZ` переносить и переименовывать нельзя.
3. Карта в разъём SD (zc), в TS-BIOS (Shift+F12) выбрать её загрузочным
   устройством — загрузится Wild Commander, `ENTER` на `OXZTFTD.SPG`
   (или `OXZUFO.SPG`) запускает игру. `wc.ini` уже ставит 14 МГц
   (`CPU_FREQ=2`).
4. Сохранения пишутся на карту (`fat_write` по месту) — защита записи
   должна быть снята.

Данные `*.PAK` сконвертированы из оригинальных игр и распространению не
подлежат (`06_original_data.md`): в репозитории их нет, каждый собирает
карту из своей копии.
