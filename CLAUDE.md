# Правила проекта OpenXComZX

- **Все артефакты — в `tmp/` в корне проекта** (сборка, логи, снимки
  экрана, промежуточные файлы, сценарии тестов). **Писать за пределами
  рабочего дерева `D:\ProjectWork\OpenXComZX` запрещено** (в т.ч. в системный
  TEMP и scratchpad). Исключение — служебная память Claude.
- **Всегда отвечать пользователю на русском языке.** Отчёты субагентов и
  англоязычный вывод инструментов пересказывать по-русски. Идентификаторы,
  имена регистров и файлов не переводить.
- Все находки, решения и важные факты записывать в `project_docs/`
  (оглавление — `project_docs/README.md`, хронология —
  `project_docs/findings_log.md`). Утверждения о железе и коде — со ссылкой
  на файл в `REF/`.
- Цель: сильно адаптированный порт OpenXcom (X-COM: UFO Defense) на
  TS-Config (ZX Evolution) с опциональной платой OPL3.
- Тулчейн: SDCC 4.5 + sdasz80 + Node.js (для скриптов и конвертера данных).
  Python не установлен — не использовать.
- `unreal/` — эмулятор Unreal (SDL2 + ImGui, свой git). Это **копия**,
  пользователь разрешил менять её как угодно: добавлять отладочные средства,
  тестовый режим, пересобирать. Запуск:
  `unreal/build/debug/Unreal.exe -c <ini> -l <метки> -b <точки останова>`,
  SPG — через `[AUTOLOAD] snapshot=` в своём ini. Подробности —
  `project_docs/01_environment.md`.
- `REF/` — справочные материалы, не редактировать.
- Сборка и тесты (подробно — `project_docs/07_debug_tools.md`):
  `powershell -File tools\build.ps1`,
  `powershell -File tools\run.ps1 -Script tests\selftest.oxs -Headless`,
  `powershell -File tools\run.ps1 -Script tests\ui_geoscape.oxs -Headless`,
  `powershell -File tools\run.ps1 -Script tests\campaign.oxs -Headless`,
  также `tests\lab.oxs`, `transfer.oxs`, `craft.oxs`, `ufopaedia.oxs`, `month.oxs`,
  `aliens.oxs`, `dogfight.oxs`, `dogfight2.oxs`, `basedefense.oxs`, `ironman.oxs`,
  `globe.oxs` (скорость глобуса по зумам — `tools\globeprof.ps1`)
  (`ufopaedia_ufo.oxs` — после сборки `-Game UFO`;
  все разом — `powershell -File tools\runtests.ps1`), `month.oxs`, `aliens.oxs`;
  все разом — `powershell -File tools\runtests.ps1` (итог «имя=код(кадров)»;
  сценарии, кроме `aliens`, выключают пришельцев `poke _alien_off 1`)
  (код выхода 0 — тест прошёл; снимки окон — `tmp/shots/<тема>/`,
  листы — `powershell -File tools\shotsheet.ps1 -Dir … -Out …`, новые окна —
  всегда со снимками; сохранения эмулятора — `tmp/saves/`). Эмулятор пересобирать
  `cmake --build unreal/build/oxz -j 2`. Профилировщик — команды сценария
  `profile on/off` (07 §6).
- SDCC 4.5.0 портит сравнение байта в A с глобальной переменной, если
  значение нужно дальше (`if (k == g) …; g = k;`): сравнивать с локальной
  копией. `tools/checkasm.js` ловит это при сборке. Библиотечный
  `__mulsint2slong` SDCC 4.5 неверен (знак по младшему байту) — заменён
  `src/kernel/win0/mul32.s`. Литеральный указатель на структуру с массивом
  (`((state_t *)0xC000)->base[0]`) роняет SDCC — только `__at`-переменные.
- Состояние кампании — `src/inc/state.h` (`ST`, страницы #06–#07, в Win3 на
  время вызовов экранов), логика — `src/game/` (банки 7–8, 16–19: месяц, сфера,
  пришельцы, НЛО — 08 §6.1), сохранение —
  дамп страниц (`project_docs/12_game_state.md`). Не держать указатели в `ST`
  через смену Win3, не делать `ST` приёмником `far_read`/`str_copy`.
- Приоритет — X-COM: Terror from the Deep, но всё универсально для UFO и
  TFTD (как OpenXcom). Конвертер данных — C#, .NET Framework 4.8, один exe
  (`tools/OxzConv`, сборка `powershell -File tools\dotnet.ps1 build
  tools\OxzConv\OxzConv.csproj -c Release`, запуск
  `tmp\oxzconv\bin\Release\OxzConv.exe --game <каталог игры> --out tmp\sd
  --preview tmp\preview`; `project_docs/09_converter.md`). Проверять на обеих
  играх из `Steam/`. dotnet — только через `tools/dotnet.ps1` (кэши в tmp/).
- Звук: 4 режима, выбор в настройках (`project_docs/11_sound.md`).
- Не править текстовые файлы через PowerShell `Get-Content`/`Set-Content`
  (PS 5.1 портит UTF-8 без BOM) — только инструментами Edit/Write.
- Регистры TS-Config — только из `src/inc/tsconf.h` (сверен с эмулятором);
  заголовок `REF/src_sdcc/inc/tsconf.h` содержит ошибки.
- Раскладка памяти и банкинг — `project_docs/08_ui_port_plan.md` §4:
  Win0 ядро (только ассемблер, ~5.7 КБ из 14; исходники — `src/kernel/win0/`), Win1 данные, Win2 банки
  (`__banked`), Win3 дальние данные. Страницы #F0–#FF не трогать. Банки —
  массив `$banks` в `tools/build.ps1` (таблица файлов — 08 §6.1); новый C-код —
  только в банки.
- Большие пакеты (фоны `BACK.PAK`, `UFOP.PAK`, `ITEMS.PAK`) читаются с
  SD-карты (`src/kernel/sd.s`, `fat.c`, `sdres.c`, банк 12;
  `project_docs/13_sd_card.md`); образ для эмулятора `tmp/sdimg/oxz.img`
  собирает `build.ps1`. DMA — прямыми регистрами с опросом `DMAStatus`
  (очередь `dmaq` не запущена).
- Целевое железо — с VDAC: палитра в CRAM с битом 15 (линейный RGB555),
  эмулятор — `TS_VDAC=5BIT` (02 §4).
- **Наставления пользователя (2026-09-15):**
  - все недоделки и идеи — в `project_docs/14_todo.md` (пополнять сразу);
  - мелочи интерфейса OpenXcom переносить обязательно (рамка габаритов постройки,
    подсказки при наведении, мигание, подсветки) — «такие мелочи всё испортят»;
  - перерисовывать только изменившееся (`ui_dirty(slot)`, `ui_dirty_row(slot, row)`
    вместо «вернуть 1» / `A_DYN` / `A_REDRAW`), но без фанатизма — учёт не должен
    съедать выигрыш;
  - оптимизировать сначала на C; ассемблер — только системное (диск, DMA, прерывания)
    и явные тормоза, горячие места — в конце по профилю;
  - **Win0 — только суперсистемное и суперглобальное, нужное обоим режимам (геоскейп
    и бой), и всё на ассемблере**: старт, ISR, джампер, рантайм, страницы, дальняя
    память, ядро ресурсов, вывод глифов. Текст, графика, SD/FAT, интерфейс, логика —
    в страницах-банках (`project_docs/14_todo.md` §1.3). Страниц 256 − 16;
  - новые окна — всегда со снимками (`tmp/shots/<тема>/`, листы — shotsheet).
- **Git (с 2026-09-15, по просьбе пользователя): коммитить постоянно** — после каждого
  законченного и проверенного шага (сборка + нужные тесты), сообщения по-русски.
  В репозитории — исходники, инструменты, тесты, документы; `.gitignore` исключает `tmp/`,
  `Steam/` (данные оригинала), `REF/`, `unreal/` (своя история), `bin/`, `obj/`.
- SDCC 4.5 путает байты в `-(x >> 8) - 1` со знаковым расширением int16 (отсев ячеек
  глобуса) — такие сравнения делать байтами. sdasz80 падает на аргументе макроса с
  пробелами (`TADD PK0 + 2, ix`) — писать `PK0+2`.
- Всё, что читает DMA из Win0/Win1, — только буферы `src/kernel/dmabuf.s`
  (DMA игнорирует бит 0 адреса, SDCC не выравнивает переменные). Оригинальные данные игры —
  в `Steam/`, не распространять; в порт идут только данные, сконвертированные
  из копии пользователя.
